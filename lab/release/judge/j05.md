## Security fixes

v2.1.0 fixes eight vulnerabilities in three servers. Upgrade
`@modelcontextprotocol/server-filesystem` and `@modelcontextprotocol/server-everything`
to 2.0.1, and `mcp-server-fetch` to 2026.10.24.

| Package | Affected | Fixed in |
| --- | --- | --- |
| `@modelcontextprotocol/server-filesystem` | 1.0.0 through 2.0.0, and date versions through 2026.8.31 | 2.0.1 |
| `@modelcontextprotocol/server-everything` | 1.0.0 through 2.0.0, and date versions 2025.9.24 through 2026.8.31 | 2.0.1 |
| `mcp-server-fetch` | through 2026.10.19 | 2026.10.24 |

### `@modelcontextprotocol/server-filesystem` 2.0.1

* **Writes stay inside the directory that was checked** (Linux and macOS). A parent directory swapped for a symlink between the access check and the write can no longer redirect `write_file`, `edit_file`, `create_directory` or the `move_file` destination outside the allowed directories. **On Windows this is only partly fixed**; the advisory says what is still exposed and how to configure around it ([GHSA-53mr-w429-c597](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-53mr-w429-c597))
* **Paths are checked exactly as they are used.** The access check no longer strips a trailing quote or whitespace that the file operation keeps, so a sibling directory named after an allowed one with that suffix is no longer reachable ([GHSA-7rgq-gccq-qphx](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-7rgq-gccq-qphx))
* **A symlink spelled in a different letter case no longer passes the symlink check** for a new path on a case-insensitive volume, such as macOS's default. This was a regression in 2026.8.31 ([GHSA-4gxg-m5jx-9j57](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-4gxg-m5jx-9j57))
* **`list_directory_with_sizes` checks each entry before reading its size**, so a symlink inside an allowed directory no longer reveals the size and modification time of a file outside it ([GHSA-hhwq-wxfx-cj7g](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-hhwq-wxfx-cj7g))

### `@modelcontextprotocol/server-everything` 2.0.1

* **The HTTP and SSE transports refuse requests from other web origins.** They now check the `Origin` header and no longer send `Access-Control-Allow-Origin: *`, so a web page the user visits can no longer call the server's tools (such as `get-env`) or read their results ([GHSA-mvf5-2qqv-rg3c](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-mvf5-2qqv-rg3c))

### `mcp-server-fetch` 2026.10.24

* **The address check and the connection use the same host name.** For an internationalized (IDNA) host name, the server used to check one form of the name and connect to another, which could reach an internal address ([GHSA-v38p-wf49-hx2j](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-v38p-wf49-hx2j))
* **NAT64 addresses are judged by the IPv4 address they carry.** An address in `64:ff9b::/96` that wraps a private, loopback or link-local IPv4 address is now refused, as an IPv4-mapped one already was ([GHSA-66qx-2266-pmj6](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-66qx-2266-pmj6))
* **robots.txt is checked again after every redirect**, not only for the URL first requested ([GHSA-3jqg-r5pp-rmp2](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-3jqg-r5pp-rmp2))

### Upgrading from a date-versioned npm release

The TypeScript servers moved from date versions (2025.x, 2026.x) to semantic versions in 1.0.0. Package managers rank 2.0.1 below every 2025.x and 2026.x version, so they won't offer it as an upgrade. If you are on a date version, install 2.0.1 explicitly, for example `npm install @modelcontextprotocol/server-filesystem@2.0.1`.

# CANDIDATE A

## MCP servers v2.1.0

This release is mostly security hardening for the `filesystem`, `fetch` and `everything` servers, plus dependency updates. No tools were added, removed or renamed.

Published versions:

- `@modelcontextprotocol/server-everything` 2.0.1
- `@modelcontextprotocol/server-filesystem` 2.0.1
- `@modelcontextprotocol/server-memory` 2.0.1
- `@modelcontextprotocol/server-sequential-thinking` 2.0.1
- `mcp-server-fetch` 2026.10.24
- `mcp-server-git` 2026.10.24
- `mcp-server-time` 2026.10.24

Details of the security fixes will follow in GitHub security advisories.

### Breaking changes

- **everything:** The HTTP transports (Streamable HTTP and HTTP+SSE) now refuse browser requests from non-localhost origins with `403 Forbidden`. [#5236](https://github.com/modelcontextprotocol/servers/pull/5236)
  - Localhost origins (`localhost`, `127.0.0.1`, `[::1]`, any port) still work, including the MCP Inspector.
  - Clients that send no `Origin` header, which is every non-browser client, are unaffected.
  - Browser pages served from other origins must now be changed or proxied.

### Security fixes

**filesystem**

- Paths are checked more strictly, including paths that do not exist yet and quoted or whitespace-padded names. Quotes and spaces are no longer stripped when checking a path for file operations.
- Directory listings no longer report the size of a file that a symlink points to outside the allowed directories.
- Writes are anchored to their checked directory, so a directory swapped for a symlink mid-operation cannot redirect them.
- Writes no longer follow a symlink swapped in after the path was checked.
- On case-insensitive file systems (macOS and Windows), a name spelled with different letter case can no longer slip past a symlink check.
- A file in the way of a new directory is now handled the same way on every platform.

**fetch**

- Every redirect hop of a tool fetch is now checked against the robots.txt of the host it leads to.
- IPv4-mapped (`::ffff:0:0/96`) and NAT64 (`64:ff9b::/96`) addresses are judged by the IPv4 address they carry, so they can no longer reach private addresses.
- The private-address check now uses the exact host name the connection uses, so international host names can no longer be checked as one name but fetched as another.

**everything**

- See the breaking change above for origin checks on the HTTP transports.

### Dependency updates

- Upgraded the MCP TypeScript SDK to 2.4.0 and its Node.js adapter to 2.1.2. [#5245](https://github.com/modelcontextprotocol/servers/pull/5245)
- Refreshed packages with published advisories: `zod` 4.6, `body-parser` 2.4.0, `undici`, `ip-address`, `fast-uri`, `launch-editor`, and `vitest` with `@vitest/coverage-v8` 4.1.12.
- fetch: bumped `certifi` to 2026.10.19. [#5244](https://github.com/modelcontextprotocol/servers/pull/5244)
- git: bumped `gitpython` to 3.2.1 for CVE-2026-114145.

### Other

- Tests: memory's file-error test accepts either error message form on any platform ([#5246](https://github.com/modelcontextprotocol/servers/pull/5246)), and sequentialthinking's schema test matches zod 4.6.
- CI and release automation: version PRs now get DCO and Everything interface-diff checks.
- Contributor docs and skills: all work happens in a fresh worktree, the session-start instructions check was added, and advisory follow-up cards are documented.
- Release preparation: version packages and Python CalVer stamping ([#5242](https://github.com/modelcontextprotocol/servers/pull/5242), [#5248](https://github.com/modelcontextprotocol/servers/pull/5248)).


# CANDIDATE B

## MCP servers v2.1.0

This release is mostly security hardening for the `filesystem`, `fetch` and `everything` servers, plus dependency updates. Upgrading is recommended for everyone using these servers.

Published versions: `@modelcontextprotocol/server-filesystem` 2.0.1, `@modelcontextprotocol/server-everything` 2.0.1, and `mcp-server-fetch` 2026.10.24. The other servers have only dependency and test updates.

### Security fixes

Details for these fixes will follow in GitHub security advisories.

**filesystem**

- Directory listings no longer report the size of a file that a symlink points to outside the allowed directories. [#5234](https://github.com/modelcontextprotocol/servers/pull/5234)
- Paths with leading or trailing quotes or spaces are now checked as written, so they can't be matched against a different file than the one used. [#5236](https://github.com/modelcontextprotocol/servers/pull/5236), [#5237](https://github.com/modelcontextprotocol/servers/pull/5237)
- Write operations now stay inside the directory that was checked, even if a folder on the path is swapped for a symlink mid-operation. [#5235](https://github.com/modelcontextprotocol/servers/pull/5235), [#5238](https://github.com/modelcontextprotocol/servers/pull/5238)
- A file sitting where a directory is expected is now handled the same way on every platform.

**fetch**

- Private-address blocking now checks the same host name the connection actually uses, so non-ASCII host names can't slip past it. [#5239](https://github.com/modelcontextprotocol/servers/pull/5239)
- IPv4 addresses wrapped in IPv4-mapped (`::ffff:0:0/96`) or NAT64 (`64:ff9b::/96`) IPv6 addresses are now judged by the IPv4 address inside. [#5240](https://github.com/modelcontextprotocol/servers/pull/5240)
- Each redirect of a tool fetch is now checked against the robots.txt of the site it leads to. Use `--ignore-robots-txt` to turn this off. [#5241](https://github.com/modelcontextprotocol/servers/pull/5241)

**everything**

- The Streamable HTTP and HTTP+SSE transports now refuse browser requests whose `Origin` is not `localhost`, `127.0.0.1` or `[::1]`, with `403 Forbidden`. Clients that send no `Origin` header, such as non-browser clients, are unaffected. The MCP Inspector on localhost still works.

### Breaking changes

- `everything`: a browser page served from a non-localhost origin can no longer reach the HTTP transports (see above). Previously any origin was allowed.
- `fetch`: tool fetches that redirect to a site whose robots.txt disallows the request are now refused, unless `--ignore-robots-txt` is set.

### Dependencies

- Upgraded the MCP TypeScript SDK to 2.4.0 and its Node.js adapter to 2.1.2. [#5245](https://github.com/modelcontextprotocol/servers/pull/5245)
- Updated packages to pick up fixes for published vulnerabilities: `zod`, `body-parser`, `undici`, `ip-address`, `fast-uri`, `launch-editor` and `vitest`.
- Updated `gitpython` in the `git` server's lockfile.
- Updated `certifi` in the `fetch` server's lockfile. [#5244](https://github.com/modelcontextprotocol/servers/pull/5244)

### Other

- Tests: made the `memory` and `sequentialthinking` tests independent of platform and `zod` message differences. [#5246](https://github.com/modelcontextprotocol/servers/pull/5246)
- CI and tooling: DCO and the Everything interface diff now run on automated version PRs, and a session-start check flags stale agent instructions. [#5222](https://github.com/modelcontextprotocol/servers/pull/5222), [#5219](https://github.com/modelcontextprotocol/servers/pull/5219)
- Docs: contributor and release guidance updates, including how advisory follow-ups are tracked. [#5220](https://github.com/modelcontextprotocol/servers/pull/5220), [#5221](https://github.com/modelcontextprotocol/servers/pull/5221), [#5233](https://github.com/modelcontextprotocol/servers/pull/5233)
- Release preparation and version bumps. [#5242](https://github.com/modelcontextprotocol/servers/pull/5242), [#5247](https://github.com/modelcontextprotocol/servers/pull/5247), [#5248](https://github.com/modelcontextprotocol/servers/pull/5248), [#5249](https://github.com/modelcontextprotocol/servers/pull/5249)
