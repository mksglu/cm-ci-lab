## Security: Node.js runtime and CA certificate updates (October 2026)

On October 20, 2026, eMudhra disclosed that the private keys for eight of its intermediate CA certificates could be recovered from the public certificates. On October 21, Node.js shipped [security releases](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases) that update its bundled CA certificates for the compromise and fix several unrelated high-severity runtime CVEs. On October 23, Python's `certifi` 2026.10.23 removed the eMudhra roots `emSign Root CA - C1` and `emSign ECC Root CA - C3`.

**How these servers stand**

- **The TypeScript servers rely on the Node.js runtime for certificate checks.** They ship no CA certificates of their own. Only `server-everything` makes outbound HTTPS requests (`gzip-file-as-resource`), and the Node.js it runs on verifies them. `server-filesystem`, `server-memory` and `server-sequential-thinking` make no network connections.
- **`mcp-server-fetch` verifies HTTPS against the `certifi` bundle**, through `httpx`. Installing from PyPI (`uvx mcp-server-fetch`, `pip install mcp-server-fetch`) resolves the current `certifi`, 2026.10.23 or later. The repository's `fetch` Dockerfile installs from its lockfile, which this release moves to `certifi` 2026.10.23 (#5341).
- **`mcp-server-git` and `mcp-server-time` make no network connections.**

**If you run a TypeScript server from npm (`npx` or a global install)**

It runs on your Node.js, which we can't update for you. Please run Node.js **24.22.1 or 26.12.1, or later**, and check with `node --version`. The packages' `engines` field accepts any Node.js 24, so npm won't warn you about an older, unpatched runtime.

**If you run `mcp-server-fetch` from an existing environment**

An environment created before October 23 keeps its older `certifi`. Refresh it with `uvx --refresh mcp-server-fetch`, or `pip install -U certifi`.

# CANDIDATE A

## Highlights

- **Security fixes** in the git and fetch servers, and in `everything`'s `gzip-file-as-resource` tool.
- **Many filesystem fixes**, including moving files across drives and more reliable handling of allowed directories.
- **Fetch handles more real-world pages**: pages that hide content until scripts run, pages with declared charsets, and sites with a missing Content-Type.

## Breaking changes

- `everything`'s `get-env` tool now masks values that look like credentials by default. ([#5293](https://github.com/modelcontextprotocol/servers/pull/5293))
- `mcp-server-fetch` now requires `readabilipy>=0.3.0`. This only matters if you pin an older version. ([#5311](https://github.com/modelcontextprotocol/servers/pull/5311))

## Security

- **git**: Fixed a security issue (GHSA-w766-5x43-whvw). The server now also checks the directories git actually opens for a repository, not just the path you pass. Details stay with the advisory. ([#5333](https://github.com/modelcontextprotocol/servers/pull/5333))
- **fetch**: Blocks IPv4-compatible IPv6 addresses (`::/96`). ([#5301](https://github.com/modelcontextprotocol/servers/pull/5301))
- **fetch**: Refuses a model-initiated fetch when `robots.txt` answers with a 5xx error. ([#5299](https://github.com/modelcontextprotocol/servers/pull/5299))
- **everything**: `gzip-file-as-resource` now refuses private and non-public addresses on every redirect hop. ([#5295](https://github.com/modelcontextprotocol/servers/pull/5295))

## Filesystem

- Moving a file across filesystems now works by copying it, instead of failing. Directories are still refused. ([#5322](https://github.com/modelcontextprotocol/servers/pull/5322))
- Client Roots are accepted in the form the client advertises, as well as their resolved path. ([#5317](https://github.com/modelcontextprotocol/servers/pull/5317))
- A failed `realpath` on an allowed directory is retried once before the directory is dropped. ([#5318](https://github.com/modelcontextprotocol/servers/pull/5318))
- Allowed directories with the wrong letter case are respelled to match the disk. ([#5319](https://github.com/modelcontextprotocol/servers/pull/5319))
- Slow `realpath`, `readdir` and recursive walks are now bounded, so a huge tree cannot hang a call. ([#5326](https://github.com/modelcontextprotocol/servers/pull/5326))
- Overwrite checks compare files by exact identity, so very large inode numbers no longer cause mistakes. ([#5325](https://github.com/modelcontextprotocol/servers/pull/5325))
- `head` no longer leaves a stray `\r` on lines from CRLF files. ([#5324](https://github.com/modelcontextprotocol/servers/pull/5324))
- `tail` no longer counts a final newline as a line. ([#5316](https://github.com/modelcontextprotocol/servers/pull/5316))

# CANDIDATE B

## Highlights

- **`everything`: safer defaults.** `get-env` now hides credential-like values, and `gzip-file-as-resource` refuses to fetch from private or internal addresses. Both can be switched back (see Breaking changes).
- **`filesystem`: more reliable.** It can move files across disks, no longer hangs on slow cloud-backed folders, and handles Windows and macOS path quirks better.
- **`fetch`: better page extraction and stricter safety checks.** It decodes more pages correctly, recovers content hidden until hydration, and can run without Node.js.
- **`git`: a security fix** (GHSA-w766-5x43-whvw), plus fixes for branch creation and non-ASCII paths.

## Breaking changes

- `everything`: `get-env` now returns `"<redacted>"` for credential-like variables. Names count when a segment is `KEY`, `TOKEN`, `SECRET`, `PASSWORD`, `PASSWD`, `CREDENTIAL`, `AUTH` or `COOKIE`. Set `GET_ENV_INCLUDE_SECRETS=1` to get every value unmasked. [#5293](https://github.com/modelcontextprotocol/servers/pull/5293)
- `everything`: `gzip-file-as-resource` now refuses loopback, private, link-local and other non-public addresses, on the URL and on every redirect. Set `GZIP_ALLOW_PRIVATE_IPS=1` to fetch from a local or private origin as before. [#5295](https://github.com/modelcontextprotocol/servers/pull/5295)
- `everything`: `GZIP_ALLOWED_DOMAINS` is now applied to every redirect hop, not only the first URL. [#5295](https://github.com/modelcontextprotocol/servers/pull/5295)
- `fetch`: an autonomous fetch is now refused when the site's `robots.txt` answers with a 5xx error. [#5299](https://github.com/modelcontextprotocol/servers/pull/5299)
- `fetch`: IPv4-compatible IPv6 addresses (`::/96`) are now refused, like other non-public addresses. [#5301](https://github.com/modelcontextprotocol/servers/pull/5301)
- `fetch`: now requires `readabilipy` 0.3.0 or later. [#5311](https://github.com/modelcontextprotocol/servers/pull/5311)
- `filesystem`: `read_text_file` with `tail` now returns the correct number of lines for a file ending in a newline. It used to return one too few. [#5316](https://github.com/modelcontextprotocol/servers/pull/5316)
- `filesystem`: `read_text_file` with `head` no longer leaves `\r` at the end of lines in CRLF files. [#5324](https://github.com/modelcontextprotocol/servers/pull/5324)

## Security

- `git`: fixes a vulnerability, [GHSA-w766-5x43-whvw](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-w766-5x43-whvw). The server now checks the directories git opens for a repository, not only the path given. Details are in the advisory. [#5333](https://github.com/modelcontextprotocol/servers/pull/5333)
- `everything`: `get-env` and `gzip-file-as-resource` are hardened (see Breaking changes). [#5293](https://github.com/modelcontextprotocol/servers/pull/5293), [#5295](https://github.com/modelcontextprotocol/servers/pull/5295)
- `filesystem`: a symlink that was retargeted inside an allowed directory is now checked before anything is created under it.
- `filesystem`: a file copied across disks is created readable only by its owner. The source is kept unless the copy is in place. [#5322](https://github.com/modelcontextprotocol/servers/pull/5322)

## New features

- `filesystem`: `get_file_info` reports a file's hard-link count as a `hardLinks` line. The README now notes that editing a hard-linked file changes it at every name. [#5315](https://github.com/modelcontextprotocol/servers/pull/5315)
- `filesystem`: `move_file` can move a regular file between allowed directories on different filesystems. It used to fail with `EXDEV`. Directories still can't be moved across filesystems and now say so. [#5322](https://github.com/modelcontextprotocol/servers/pull/5322)
- `fetch`: a new `--no-readability-js` option keeps content extraction off Node.js. [#5307](https://github.com/modelcontextprotocol/servers/pull/5307)
- `git`: `git_create_branch` works on a detached HEAD and accepts a commit, such as a SHA or `HEAD~2`, as the base. [#5309](https://github.com/modelcontextprotocol/servers/pull/5309)

## Fixes

### filesystem

- Searching and directory listing no longer hang on slow folders such as macOS CloudStorage, iCloud Drive or network mounts. Each lookup now times out after 15 seconds with an error naming the path, and walks stop after 100,000 entries. [#5326](https://github.com/modelcontextprotocol/servers/pull/5326)
- `search_files` applies `excludePatterns` before touching an entry, so excluded folders are never visited. [#5326](https://github.com/modelcontextprotocol/servers/pull/5326)
- A path that spells an allowed directory in a different letter case is accepted on case-insensitive file systems (Windows, default macOS). [#5319](https://github.com/modelcontextprotocol/servers/pull/5319)
- A client Root is now allowed in the form the client advertised, as well as its resolved form. This fixes symlinked Roots such as `/tmp` on macOS. [#5317](https://github.com/modelcontextprotocol/servers/pull/5317)
- A directory whose first `realpath` fails, for example right after `subst` on Windows, is retried instead of being lost. [#5318](https://github.com/modelcontextprotocol/servers/pull/5318)
- `write_file` and `edit_file` no longer refuse every existing file on some Windows setups, and compare large Windows file ids exactly. [#5325](https://github.com/modelcontextprotocol/servers/pull/5325)
- Cross-device moves keep sub-millisecond and pre-1970 modification times. [#5322](https://github.com/modelcontextprotocol/servers/pull/5322)

### fetch

- Pages are decoded using the charset their HTML declares, and a declared charset that isn't ASCII-compatible is ignored. [#5302](https://github.com/modelcontextprotocol/servers/pull/5302)
- Extraction works on non-cp1252 pages on Windows. [#5311](https://github.com/modelcontextprotocol/servers/pull/5311)
- Server-rendered content that is hidden until hydration is recovered. [#5308](https://github.com/modelcontextprotocol/servers/pull/5308)
- `role=complementary` is treated as page furniture, like `aside`, and `!important` is matched in any case.
- A response with no `Content-Type` is treated as HTML only when its body is, and the raw output names the missing type. [#5300](https://github.com/modelcontextprotocol/servers/pull/5300)
- An empty page no longer crashes extraction. [#5304](https://github.com/modelcontextprotocol/servers/pull/5304)
- `beautifulsoup4` is now declared as a dependency. [#5323](https://github.com/modelcontextprotocol/servers/pull/5323)

### git

- Non-ASCII file names print as written instead of as octal escapes. Undecodable bytes in diffs are replaced instead of causing errors. [#5312](https://github.com/modelcontextprotocol/servers/pull/5312)

### memory

- A failed `memory.json` to `memory.jsonl` migration now stops startup with a clear error. Before, the server silently started with an empty graph. [#5291](https://github.com/modelcontextprotocol/servers/pull/5291)
- Writes keep fields the server doesn't model on stored entities and relations, such as `createdAt`. Before, they were dropped on every write. [#5292](https://github.com/modelcontextprotocol/servers/pull/5292)

### time

- The Docker image now expands `LOCAL_TIMEZONE` when it runs, not at build time. [#5294](https://github.com/modelcontextprotocol/servers/pull/5294)

### everything

- `gzip-file-as-resource` fails with an error naming the URL and status on a non-2xx response, instead of gzipping the error page. [#5290](https://github.com/modelcontextprotocol/servers/pull/5290)
- `trigger-elicitation-request` summarizes the fields the form actually asks for, and no longer reports `color` or `petType`. [#5289](https://github.com/modelcontextprotocol/servers/pull/5289)
- `get-tiny-image` and `get-annotated-message` return a valid PNG, after the corrupt color-profile chunk was removed. [#5298](https://github.com/modelcontextprotocol/servers/pull/5298)
- In `get-resource-links`, the `isOdd` flag is renamed `isText`. Behavior is unchanged. [#5297](https://github.com/modelcontextprotocol/servers/pull/5297)
