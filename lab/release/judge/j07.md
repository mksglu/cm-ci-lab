## Security: Node.js runtime and CA certificate updates (October 2026)

On October 20, 2026, eMudhra disclosed that the private keys for eight of its intermediate CA certificates could be recovered from the public certificates. On October 21, Node.js shipped [security releases](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases) that update its bundled CA certificates for the compromise and fix several unrelated high-severity runtime CVEs. On October 23, Python's `certifi` 2026.10.23 removed the eMudhra roots `emSign Root CA - C1` and `emSign ECC Root CA - C3`.

**How these servers stand**

- **The TypeScript servers rely on the Node.js runtime for certificate checks.** They ship no CA certificates of their own. Only `server-everything` makes outbound HTTPS requests (`gzip-file-as-resource`), and the Node.js it runs on verifies them. `server-filesystem`, `server-memory` and `server-sequential-thinking` make no network connections.
- **`mcp-server-fetch` verifies HTTPS against the `certifi` bundle**, through `httpx`. Installing from PyPI (`uvx mcp-server-fetch`, `pip install mcp-server-fetch`) resolves the current `certifi`, 2026.10.23 or later. The repository's `fetch` Dockerfile installs from its lockfile, which this release moves to `certifi` 2026.10.23 (#5341).
- **`mcp-server-git` and `mcp-server-time` make no network connections.**

**If you run a TypeScript server from npm (`npx` or a global install)**

It runs on your Node.js, which we can't update for you. Please run Node.js **24.22.1 or 26.12.1, or later**, and check with `node --version`. The packages' `engines` field accepts any Node.js 24, so npm won't warn you about an older, unpatched runtime.

**If you run `mcp-server-fetch` from an existing environment**

An environment created before October 23 keeps its older `certifi`. Refresh it with `uvx --refresh mcp-server-fetch`, or `pip install -U certifi`.

# MCP servers v2.2.0

This release is mostly fixes and hardening for the `filesystem`, `fetch`, `git` and `everything` servers, with smaller fixes to `memory` and `time`. `sequentialthinking` is unchanged.

Published versions:

| Package | Version |
| --- | --- |
| `@modelcontextprotocol/server-everything` | 2.1.0 |
| `@modelcontextprotocol/server-filesystem` | 2.1.0 |
| `@modelcontextprotocol/server-memory` | 2.0.1 |
| `mcp-server-fetch`, `mcp-server-git`, `mcp-server-time` | 2026.10.28 |

## Security

- **git:** `repo_path` checks now also cover the directories Git actually opens, so a nested repository that points outside `--repository` is refused. Fixes GHSA-w766-5x43-whvw. [#5333](https://github.com/modelcontextprotocol/servers/pull/5333)
- **everything:** `get-env` now masks the values of credential-like variables (names containing `KEY`, `TOKEN`, `SECRET`, `PASSWORD`, `AUTH` and similar) as `<redacted>`. Set `GET_ENV_INCLUDE_SECRETS=1` to see them. [#5293](https://github.com/modelcontextprotocol/servers/pull/5293)
- **everything:** `gzip-file-as-resource` refuses private and other non-public addresses on every redirect hop. New settings `GZIP_ALLOWED_DOMAINS` and `GZIP_ALLOW_PRIVATE_IPS` control this. [#5295](https://github.com/modelcontextprotocol/servers/pull/5295)
- **fetch:** IPv4-compatible IPv6 addresses (`::/96`) are now refused like other private addresses. [#5301](https://github.com/modelcontextprotocol/servers/pull/5301)
- **fetch:** An autonomous fetch is refused when `robots.txt` answers with a 5xx error. [#5299](https://github.com/modelcontextprotocol/servers/pull/5299)

## Breaking or behavior changes

- **everything:** `get-env` no longer returns secret values unless `GET_ENV_INCLUDE_SECRETS` is set. [#5293](https://github.com/modelcontextprotocol/servers/pull/5293)
- **everything:** `gzip-file-as-resource` no longer fetches private or loopback addresses unless `GZIP_ALLOW_PRIVATE_IPS` is set. [#5295](https://github.com/modelcontextprotocol/servers/pull/5295)
- **filesystem:** `tail` no longer counts a final newline as a line, and `head` returns CRLF lines without the trailing `\r`. [#5316](https://github.com/modelcontextprotocol/servers/pull/5316), [#5324](https://github.com/modelcontextprotocol/servers/pull/5324)

## New features

- **filesystem:** `get_file_info` reports the hard-link count. [#5315](https://github.com/modelcontextprotocol/servers/pull/5315)
- **fetch:** New `--no-readability-js` option keeps page extraction off Node.js. [#5307](https://github.com/modelcontextprotocol/servers/pull/5307)

## filesystem fixes

# CANDIDATE B

## Highlights

- **Security:** the git server now checks the directories Git actually uses for a repository, not only the path you pass, when `--repository` is set ([#5333](https://github.com/modelcontextprotocol/servers/pull/5333)).
- **Security:** the everything server's `get-env` tool now masks credential-like values by default ([#5293](https://github.com/modelcontextprotocol/servers/pull/5293)).
- **Filesystem:** moves across disks now work, and slow cloud-storage folders no longer stall the server.
- **Fetch:** pages that hide server-rendered content until scripts run are now extracted, and `--no-readability-js` keeps extraction off Node.js.

## Breaking changes

None.

## Security

- git: with `--repository`, a nested repository whose `.git` file, `commondir` or `core.worktree` points outside the allowed repository is now refused ([#5333](https://github.com/modelcontextprotocol/servers/pull/5333)).
- everything: `get-env` replaces the values of credential-like variables (names with KEY, TOKEN, SECRET, PASSWORD, AUTH and similar parts) with `<redacted>` ([#5293](https://github.com/modelcontextprotocol/servers/pull/5293)).
- everything: set `GET_ENV_INCLUDE_SECRETS=1` to get the old unmasked output back ([#5293](https://github.com/modelcontextprotocol/servers/pull/5293)).
- everything: `gzip-file-as-resource` now refuses non-public addresses on every redirect hop and accepts public exceptions in IPv6 allowlist entries ([#5295](https://github.com/modelcontextprotocol/servers/pull/5295)).
- fetch: IPv4-compatible IPv6 addresses (`::/96`, such as `::127.0.0.1`) are now refused ([#5301](https://github.com/modelcontextprotocol/servers/pull/5301)).
- fetch: an autonomous fetch is now refused when robots.txt answers with a server error (5xx), as RFC 9309 says ([#5299](https://github.com/modelcontextprotocol/servers/pull/5299)).

## Features

- fetch: new `--no-readability-js` option extracts HTML with the pure-Python extractor and never starts Node.js ([#5307](https://github.com/modelcontextprotocol/servers/pull/5307)).
- filesystem: `get_file_info` now reports a file's hard-link count (`hardLinks`) ([#5315](https://github.com/modelcontextprotocol/servers/pull/5315)).
- filesystem: `move_file` now moves a regular file across filesystems by copying it ([#5322](https://github.com/modelcontextprotocol/servers/pull/5322)).
