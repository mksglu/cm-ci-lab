## Security fixes

v2.1.0 fixes eight vulnerabilities in three servers. Upgrade
`@modelcontextprotocol/server-filesystem` and `@modelcontextprotocol/server-everything`
to 2.0.1, and `mcp-server-fetch` to 2026.10.24.

| Package | Affected | Fixed in |
| --- | --- | --- |
| `@modelcontextprotocol/server-filesystem` | 1.0.0 through 2.0.0, and date versions through 2026.8.31 | 2.0.1 |
| `@modelcontextprotocol/server-everything` | 1.0.0 through 2.0.0, and date versions 2025.9.24 through 2026.8.31 | 2.0.1 |
| `mcp-server-fetch` | through 2026.10.19 | 2026.10.24 |

### `@modelcontextprotocol/server-filesystem` 2.0.1

* **Writes stay inside the directory that was checked** (Linux and macOS). A parent directory swapped for a symlink between the access check and the write can no longer redirect `write_file`, `edit_file`, `create_directory` or the `move_file` destination outside the allowed directories. **On Windows this is only partly fixed**; the advisory says what is still exposed and how to configure around it ([GHSA-53mr-w429-c597](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-53mr-w429-c597))
* **Paths are checked exactly as they are used.** The access check no longer strips a trailing quote or whitespace that the file operation keeps, so a sibling directory named after an allowed one with that suffix is no longer reachable ([GHSA-7rgq-gccq-qphx](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-7rgq-gccq-qphx))
* **A symlink spelled in a different letter case no longer passes the symlink check** for a new path on a case-insensitive volume, such as macOS's default. This was a regression in 2026.8.31 ([GHSA-4gxg-m5jx-9j57](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-4gxg-m5jx-9j57))
* **`list_directory_with_sizes` checks each entry before reading its size**, so a symlink inside an allowed directory no longer reveals the size and modification time of a file outside it ([GHSA-hhwq-wxfx-cj7g](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-hhwq-wxfx-cj7g))

### `@modelcontextprotocol/server-everything` 2.0.1

* **The HTTP and SSE transports refuse requests from other web origins.** They now check the `Origin` header and no longer send `Access-Control-Allow-Origin: *`, so a web page the user visits can no longer call the server's tools (such as `get-env`) or read their results ([GHSA-mvf5-2qqv-rg3c](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-mvf5-2qqv-rg3c))

### `mcp-server-fetch` 2026.10.24

* **The address check and the connection use the same host name.** For an internationalized (IDNA) host name, the server used to check one form of the name and connect to another, which could reach an internal address ([GHSA-v38p-wf49-hx2j](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-v38p-wf49-hx2j))
* **NAT64 addresses are judged by the IPv4 address they carry.** An address in `64:ff9b::/96` that wraps a private, loopback or link-local IPv4 address is now refused, as an IPv4-mapped one already was ([GHSA-66qx-2266-pmj6](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-66qx-2266-pmj6))
* **robots.txt is checked again after every redirect**, not only for the URL first requested ([GHSA-3jqg-r5pp-rmp2](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-3jqg-r5pp-rmp2))

### Upgrading from a date-versioned npm release

The TypeScript servers moved from date versions (2025.x, 2026.x) to semantic versions in 1.0.0. Package managers rank 2.0.1 below every 2025.x and 2026.x version, so they won't offer it as an upgrade. If you are on a date version, install 2.0.1 explicitly, for example `npm install @modelcontextprotocol/server-filesystem@2.0.1`.

# CANDIDATE A

# MCP servers v2.1.0

This release is mostly security hardening for the `filesystem`, `fetch` and `everything` servers, plus dependency updates. There are no breaking changes, removals or deprecations. Upgrading is recommended for anyone running these three servers.

Package versions in this release:

- `@modelcontextprotocol/server-everything` 2.0.1
- `@modelcontextprotocol/server-filesystem` 2.0.1
- `mcp-server-fetch` 2026.10.24
- `mcp-server-git` and `mcp-server-time` 2026.10.24 (Python CalVer stamp)
- `@modelcontextprotocol/server-memory` and `@modelcontextprotocol/server-sequential-thinking` have no code changes.

## Security fixes

### filesystem

- Writes, new-file creation, directory creation and moves now stay inside the directory that was checked, so a directory swapped for a symlink mid-operation can't redirect them ([#5237](https://github.com/modelcontextprotocol/servers/pull/5237)).
- Paths with leading or trailing quotes or spaces are no longer trimmed before the allowed-directory check, so the checked path is the one actually used ([#5235](https://github.com/modelcontextprotocol/servers/pull/5235)).
- A name that differs only by letter case on case-insensitive file systems (macOS, Windows) is now resolved and checked, so it can't reach a symlink pointing outside the allowed directories ([#5236](https://github.com/modelcontextprotocol/servers/pull/5236)).
- `list_directory_with_sizes` now checks each entry, and a symlink pointing outside the allowed directories is listed without a size ([#5234](https://github.com/modelcontextprotocol/servers/pull/5234)).
- A file sitting where a directory is needed is now handled the same way on every platform.

### fetch

- Addresses in the well-known NAT64 range (`64:ff9b::/96`) are now judged by the IPv4 address they wrap, so they can't be used to reach private addresses ([#5238](https://github.com/modelcontextprotocol/servers/pull/5238)).
- The private-address check now uses the same ASCII host name the connection uses, so internationalized names can't pass the check and then connect elsewhere ([#5240](https://github.com/modelcontextprotocol/servers/pull/5240)).
- `robots.txt` is now also checked on each redirect, against the redirect target's own site, unless robots checking is turned off ([#5239](https://github.com/modelcontextprotocol/servers/pull/5239)).

### everything

- The HTTP transports (Streamable HTTP and SSE) now reject requests from browser pages that are not on a localhost origin, with a 403 ([#5241](https://github.com/modelcontextprotocol/servers/pull/5241)).
- CORS now allows only an origin that passed that check, not every origin. Non-browser clients and the Inspector from localhost still work.

## Dependency updates

- Updated the MCP TypeScript SDK to 2.4.0 and its Node.js adapter to 2.1.2 ([#5245](https://github.com/modelcontextprotocol/servers/pull/5245)).
- Updated `certifi` in `fetch` to 2026.10.19 ([#5244](https://github.com/modelcontextprotocol/servers/pull/5244)).
- Updated `gitpython` in `git` to 3.2.1 for a published vulnerability fix.
- Updated `zod` to 4.6.x, `body-parser` to 2.4.0, `undici`, `launch-editor`, and the `ip-address` and `fast-uri` pins, to clear published security advisories.
- Updated `vitest` and `@vitest/coverage-v8` to ^4.1.12 for security advisories (development only).

## Other

- Tests: made the memory and sequential-thinking tests tolerant of platform and `zod` 4.6 differences ([#5246](https://github.com/modelcontextprotocol/servers/pull/5246)).
- CI: DCO and the Everything interface diff now run on version PRs opened by automation ([#5222](https://github.com/modelcontextprotocol/servers/pull/5222)).
- Maintainer docs and tooling: a session-start check that agent instructions are current, and updates to the release, skill and advisory docs ([#5219](https://github.com/modelcontextprotocol/servers/pull/5219), [#5220](https://github.com/modelcontextprotocol/servers/pull/5220), [#5221](https://github.com/modelcontextprotocol/servers/pull/5221), [#5233](https://github.com/modelcontextprotocol/servers/pull/5233)).
- Release preparation: version bump and Python CalVer PRs ([#5242](https://github.com/modelcontextprotocol/servers/pull/5242), [#5248](https://github.com/modelcontextprotocol/servers/pull/5248), [#5247](https://github.com/modelcontextprotocol/servers/pull/5247)).


# CANDIDATE B

## MCP servers v2.1.0

This release is mostly security hardening for the `filesystem`, `fetch` and `everything` servers, plus dependency updates. No tools were added, removed or renamed. Upgrading is recommended for anyone running `filesystem`, `fetch` or the `everything` HTTP transports.

The security fixes below were developed as private security advisories. Details will follow in the GitHub security advisories.

### Security and fixes

**filesystem**

- Write, create-directory and move operations now stay inside the directory that was checked, so a directory swapped for a symlink mid-operation can't redirect a write outside the allowed directories. ([#5236](https://github.com/modelcontextprotocol/servers/pull/5236), [#5237](https://github.com/modelcontextprotocol/servers/pull/5237), [#5238](https://github.com/modelcontextprotocol/servers/pull/5238), [#5239](https://github.com/modelcontextprotocol/servers/pull/5239))
- Path checks now keep quotes and surrounding whitespace in file names instead of stripping them, so the path that is checked is the path that is used.
- Paths that differ only by letter case on case-insensitive file systems (macOS, Windows) are now checked for symlinks that leave the allowed directories.
- Directory listings no longer report the size or type of a symlink's target when that target is outside the allowed directories. ([#5234](https://github.com/modelcontextprotocol/servers/pull/5234))
- A file sitting where a directory should go now gives the same error on every platform. ([#5246](https://github.com/modelcontextprotocol/servers/pull/5246))

**fetch**

- Private-address blocking now also covers IPv6 addresses that wrap an IPv4 address through the standard NAT64 prefix (`64:ff9b::/96`).
- The address check now uses the same ASCII form of the host name that the connection uses, so internationalized host names can't be checked as one name and connected to as another.
- `robots.txt` is now checked for every redirect hop, not just the first URL. Redirects to a site that disallows the fetch are refused unless robots.txt checking is turned off.

**everything**

- The Streamable HTTP and HTTP+SSE transports now reject browser requests from non-localhost origins with a 403. Requests without an `Origin` header (non-browser clients) and requests from localhost, such as the Inspector's direct connect mode, still work. This replaces the previous allow-all CORS setting. ([#5235](https://github.com/modelcontextprotocol/servers/pull/5235))

### Dependencies

- The MCP TypeScript SDK is updated to 2.4.0, and its Node.js adapter to 2.1.2. ([#5245](https://github.com/modelcontextprotocol/servers/pull/5245))
- Dependency updates for published advisories: `zod`, `body-parser`, `undici`, `launch-editor`, and the `ip-address` and `fast-uri` pins. `gitpython` is updated in the `git` server's lockfile.
- `fetch` picks up an updated `certifi` certificate bundle. ([#5244](https://github.com/modelcontextprotocol/servers/pull/5244))

### Versions

- TypeScript servers: `everything` and `filesystem` are 2.0.1 in their `package.json`, the others are unchanged.
- Python servers (`fetch`, `git`, `time`) use CalVer `2026.10.24`.

### Other

- Test fixes for the `memory` and `sequentialthinking` servers, and a `vitest` update. ([#5246](https://github.com/modelcontextprotocol/servers/pull/5246))
- Maintainer workflow, skills and CI changes, including DCO and interface-diff checks on version PRs and a session-start check that instructions are current. ([#5219](https://github.com/modelcontextprotocol/servers/pull/5219), [#5220](https://github.com/modelcontextprotocol/servers/pull/5220), [#5221](https://github.com/modelcontextprotocol/servers/pull/5221), [#5222](https://github.com/modelcontextprotocol/servers/pull/5222), [#5233](https://github.com/modelcontextprotocol/servers/pull/5233))
