# CANDIDATE A

## Improvements

- `z.instanceof(Class).properties({...})` now checks the shape against the instance type, so keys autocomplete and unknown keys or mismatched property schemas fail to compile. ([#6600](https://github.com/colinhacks/zod/pull/6600))

This is a type-only change. The emitted JavaScript is identical. It does tighten the signature: a shape key that isn't on the instance type, or that names a method, is now a type error. Methods are excluded from the shape.

## Other

- Docs: added the 4.6.x patch highlights to the Zod 4.6 post, and reworked the `.properties()` section to lead with the check and add a Zod Mini tab. ([#6598](https://github.com/colinhacks/zod/pull/6598))
- Version bump to 4.6.5 and re-pinned the integration peers to the workspace `zod`.


# CANDIDATE B

## Improvements

- `z.instanceof(...).properties()` now takes a shape keyed off the instance type, so misspelled keys and schemas that can't accept the property's type are compile errors, and keys autocomplete. Methods are excluded from the shape. This is type-only; runtime behavior is unchanged. [#6600](https://github.com/colinhacks/zod/pull/6600)

## Other

- Docs: the `properties` section now leads with the check form (with a Zod Mini tab) and notes that `z.instanceof()` returns the exact object you pass in. [#6598](https://github.com/colinhacks/zod/pull/6598)
- Docs: added 4.6.x patch highlights to the Zod 4.6 blog post.
- Version bump and integration peer dependency re-pinning.
