# CANDIDATE A

## Fixes

- Oversized arrays, sets and maps are now rejected on `.max()`, `.length()` and `.size()` before any elements are parsed, so you get one size issue instead of one issue per bad element. Fixes #6643. ([#6652](https://github.com/colinhacks/zod/pull/6652))
- Fixed a TypeScript error (TS5115) and an `any` record input type in `z.json()` on newer TypeScript versions. ([#6645](https://github.com/colinhacks/zod/pull/6645))

## Docs

- Docs now recommend importing locales from `zod/locales` instead of using `z.locales`, which can pull every locale into esbuild and Turbopack bundles. This includes loading `en` directly in Zod Mini.
- Added Code for Japan to the bronze sponsors.

## Other

- Release workflow now stages npm versions for approval before publishing, and waits for that approval without holding a runner. ([#6622](https://github.com/colinhacks/zod/pull/6622), [#6638](https://github.com/colinhacks/zod/pull/6638))
- CI release staging logs at verbose level to help diagnose failed token exchanges.


# CANDIDATE B

## Fixes

- Oversized arrays, sets and maps now fail `.max()`, `.length()` and `.size()` before any element is parsed, so you get one size issue instead of one issue per bad element ([#6652](https://github.com/colinhacks/zod/pull/6652), fixes [#6643](https://github.com/colinhacks/zod/issues/6643)).
- Fixed a TypeScript error (TS5115) and an `any` record input type in `z.json()` on newer TypeScript versions ([#6645](https://github.com/colinhacks/zod/pull/6645)).

## Docs

- Docs now recommend importing locales from `zod/locales` instead of using `z.locales`, which bundles every locale under esbuild and Turbopack.
- The Zod Mini docs now load the `en` locale directly from `zod/locales`.
- Added Code for Japan to the bronze sponsors.

## Other

- Release workflow now stages npm versions for maintainer approval instead of publishing directly ([#6622](https://github.com/colinhacks/zod/pull/6622), [#6638](https://github.com/colinhacks/zod/pull/6638)).
