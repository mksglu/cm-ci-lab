# REVIEW A

## Review of PR #345293: hide non-user-invocable agents from the Cloud picker

The PR is already merged. The change is small and well scoped, and I found no blocking issues.

### What it does well
- **Filtering at the picker boundary.** `remoteAgents.filter(agent => agent.user_invocable !== false)` treats a missing value as visible, so default visibility is unchanged.
- **Hidden agents can't come back as warnings.** The full remote list, hidden agents included, is still passed to `getLocalCustomAgentFiles`. A hidden remote agent therefore matches its local file by name and doesn't show up as a "Missing from…" warning. The test `keeps remote visibility authoritative…` covers this.
- **Frontmatter parsing reuses `PromptFileParser`.** The tests cover CRLF line endings, trailing YAML comments, a body that only mentions the key, and a nested `metadata.user-invocable` key.
- **Errors are handled per file.** One unreadable or deleted file is logged and skipped, and the other agents are still found.
- **The condition for showing the group is correct.** It now uses `userInvocableAgents.length` rather than the raw remote count. This avoids an empty picker when every remote agent is hidden, and a test checks it.

### Suggestions (non-blocking)
1. **Sequential file reads.** The loop does `await readFile` for each non-matching local file. This is fine for a handful of agent files. If the directory can grow, `Promise.all` over the entries would remove the serial latency. The picker is built on a user-visible path, so it may be worth doing.
2. **`new PromptFileParser()` per file.** It is created inside the loop. Creating it once before the loop is cheaper and a little tidier.
3. **Filename-based matching.** Matching still relies on the file name (`agentName.toLowerCase()`). A local file whose frontmatter `name:` differs from its file name could still be misclassified. The remote-versus-local comparison was already like this, so it isn't a regression. A comment or a follow-up issue would be enough.
4. **Possible edge case.** `user_invocable: false` on a remote agent excludes it from the picker, but it could still be selected if a session was restored with that agent ID saved. I didn't check whether that restore path validates the ID. Since the linked bug is an HTTP 400, it's worth a quick check.
5. **Log wording.** `Error reading local agent ...` is clear. Consider using `error instanceof Error ? error.message : error` to avoid noisy stringification, though this is minor.

### Tests
Coverage is good. The seven cases cover visibility defaults, case-insensitive matching, local frontmatter handling, API failure, and a deleted or unreadable file. The mock setup (`vscode.FileSystemError`, `asRelativePath`, an observable `activeRepository`) is reasonable. The `FileSystemError` mock is a minimal stub with a hard-coded `code`. That works, but it could break if production code later branches on other error codes.

### Security and performance
There are no security concerns. The change reads only files inside the workspace's `.github/agents` directory and only parses them, and the content isn't executed. The performance impact is limited to the extra reads for local-only files, as noted above.

**Verdict:** Approve, with the optional cleanups above for a follow-up.
