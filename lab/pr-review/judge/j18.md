# REVIEW A

**Review of PR 37046: distrust compromised eMudhra CAs** (the PR is already merged)

**Overall:** This is a focused security fix. It bumps the verifier and root bundles, and it migrates the ML-DSA imports because the aws-lc-rs bump forces that. I found no blocking issues. A few things are worth checking.

**What looks good**
- `rustls-webpki` is raised to a floor of `0.103.16` in `Cargo.toml`. This is the version that rejects paths containing the compromised keys, cross-signed ones included. A minimum bound is the right way to stop a lockfile regression from dropping the fix.
- `webpki-roots` and `webpki-root-certs` go to 1.0.10. The transitive 0.26 users (reqwest, hyper-rustls) resolve to the 0.26.11 shim, which re-exports 1.0.10. That means a single root bundle is in use. The lockfile confirms it.
- The `mldsa.rs` change is mechanical. It moves from the `unstable::signature` paths to the stable ones. It uses `to_pkcs8v1()` to keep the exported PKCS#8 format the same, which is the correct way to avoid a silent change in WebCrypto export output.

**Concerns and suggestions**
1. **Two `aws-lc-sys` versions.** `aws-lc-rs` 1.18.2 pulls in `aws-lc-sys 0.46.0`. `deno_crypto` and `deno_crypto_provider` stay pinned to `0.40.0` through the workspace dependency (`Cargo.toml:195`). The result is two copies of AWS-LC compiled and linked. Possible effects:
   - Longer build times and a larger binary.
   - Duplicate C symbols, which is normally avoided through `links`-based prefixing. Please confirm the link step is clean on all platforms, especially Windows/NASM and the `prebuilt-nasm` feature, which only the 0.40 dependency enables.
   - Direct FFI use in `deno_crypto_provider` talks to a different AWS-LC build than `aws-lc-rs` does. Do not pass raw pointers or structs between the two.

   A follow-up that bumps the workspace `aws-lc-sys` to 0.46 would remove the duplicate.
2. **Major-version jump for `webpki-root-certs` (0.26 → 1.x).** `ext/tls` and `ext/node` consume it. The PR validated this with `cargo check -p deno_tls -p deno_node`, which is good. 1.x changed the exported types (`TrustAnchor` / `CertificateDer` constants), so a quick runtime check would add confidence, for example `tls.rootCertificates` and `deno run` against a public HTTPS host.
3. **Test coverage.** The PR adds no tests. A regression test for the distrust would be hard to do, since it needs a chain signed by a compromised key and no network. At minimum, a unit or spec test could assert that `emSign ECC Root CA - G3` is absent from `tls.rootCertificates`. That would catch a future downgrade of the bundle.
4. **Scope and hygiene (minor).** The PR bundles three things: the TLS fix, the AWS-LC ML-DSA migration, and the `deno_graph` bump. The CLAUDE.md guidance says to keep changes minimal. They are coupled here because the lockfile and CI need them together, so I think that's acceptable. The PR description also ends with an unrelated line about the `deno_graph` bump, which reads like an appended note.
5. **`pkg-config` 0.3.30 → 0.3.34.** This is a lockfile-only bump and is fine. The PR notes it is needed for the verifier.

**Security:** The change is a net improvement. The remaining risk is a stale copy of the old roots, for example if another dependency pins `webpki-roots` 0.25 or earlier. The lockfile shows only 0.26.11 and 1.0.10, so none remain. `cargo tree -i webpki-roots` could be added to CI as a guard.

**Verdict:** Approve. The duplicate `aws-lc-sys` is the main follow-up item.

# REVIEW B

**Review of PR 37046: distrust compromised eMudhra CAs** (already merged)

**Summary:** This is a security dependency bump. It moves `rustls-webpki` to 0.103.16 and `webpki-roots`/`webpki-root-certs` to 1.0.10, which drops the compromised eMudhra roots. It also bumps `aws-lc-rs` to 1.18.2 and moves ML-DSA from the `unstable` API to the stable one. The change is minimal and focused, and it does what the title says.

**Things I checked**
- **Pins:** `rustls-webpki = "0.103.16"` sets a floor, so a future lockfile refresh can't resolve below the fix. The `webpki-roots` and `webpki-root-certs` floors do the same.
- **0.26.11 wrapper:** `reqwest` and `hyper-rustls` get `webpki-roots 0.26.11`, which re-exports 1.0.10. Everything therefore uses the same fixed root bundle.
- **ML-DSA PKCS#8:** `to_pkcs8v1()` keeps the existing export format, as the description says. I couldn't confirm the exported bytes are identical to before, because I only read the diff and ran nothing.

**Concerns and suggestions**
1. **Two `aws-lc-sys` versions:** The lockfile now has `aws-lc-sys` 0.46.0 (pulled in by `aws-lc-rs` 1.18.2) and 0.40.0. The workspace pins 0.40.0 for `deno_crypto_provider` and `deno_node`. Two copies of AWS-LC means two C libraries compiled and linked, which adds binary size and build time. It could also cause symbol clashes, since the sys crates normally use a `links` key. The two versions evidently coexist and build here. Still, bump the workspace `aws-lc-sys` pin to 0.46 so only one copy remains, or confirm that `deno_crypto_provider` really needs the older one. If the older one is deliberate, a comment in `Cargo.toml` would help.
2. **No regression test:** Nothing checks that the compromised roots are rejected, for example a spec test or unit test asserting `emSign ECC Root CA - G3` is absent from the bundle. Such a test is hard to write offline, but a small check against the bundled root list would guard against a later downgrade. Without it, the `Cargo.toml` version floors are the only protection.
3. **ML-DSA coverage:** The migration to the stable API rests on the existing WebCrypto ML-DSA tests. Confirm those ran in CI. Import/export roundtrip and PKCS#8 interop would be the main things to watch.
4. **Scope:** The description also covers the `deno_graph` bump to 0.111.1, which is the third item in the title/body and is reasonable because it carries the same TLS fix. The `pkg-config` bump comes along as a transitive requirement. Overall the PR stays within scope.
5. **`webpki-root-certs` major jump:** Moving from 0.26 to 1.x is a major version change. `deno_node` and `deno_tls` compiled per the validation list. Check that no API consumers, such as `rustls_pki_types::CertificateDer` conversions, changed behavior. I saw no code changes there, so it is probably fine.

**Security:** The change is positive. It removes the eight compromised keys from path validation and from both bundled root sets. I found no new risks. The only residual risk is item 1, the duplicated AWS-LC.

**Verdict:** Approve. Item 1 is worth a follow-up, and item 2 is a nice-to-have.
