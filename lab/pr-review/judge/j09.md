# Review: PR #345293 — chat: hide non-user-invocable agents from the Cloud picker

## Summary
The PR filters remote custom agents with `user_invocable: false` out of the Cloud agent picker. It also parses frontmatter for local-only `.github/agents/*.md` files so hidden local agents don't show up as "missing from remote" warning entries. The change is small and well scoped. The rule that the remote setting wins is right: the full remote name set is still used for matching, so a local copy can't bring a hidden remote agent back. The tests are thorough. I'd approve, with the minor points below.

## Code quality / correctness
**What's good:**
- Passing the full `remoteAgents` list into `getLocalCustomAgentFiles` and filtering only for display (`copilotCloudSessionsProvider.ts:1255-1258`) is the right split. The test `keeps remote visibility authoritative when matching local files` covers it, including filenames with mixed case.
- `agent.user_invocable !== false` keeps agents visible when the field is missing, and it doesn't mix in `disable_model_invocation`. That matches how frontmatter is treated elsewhere.
- It reuses `PromptFileParser` instead of matching frontmatter with a regex. The test cases (CRLF line endings, a trailing `# comment`, the phrase only in the body, a nested key) show why that matters.
- Removing the repeated `customAgents.status === 'fulfilled'` checks makes the condition and the item list easier to read.

**Points to consider:**
1. **Unreadable local files now disappear from the picker.** Before this change, any `.md` file in `.github/agents/` produced a locked warning entry. Now a file that fails to read (permissions, a race with deletion) is only logged as a warning (`:1164-1166`). For deleted files that's correct. For a permission error, it's arguably better to keep showing the warning entry and treat visibility as the default. That's a deliberate choice and is tested, so it's not blocking. A short comment saying it's intentional would help later readers.
2. **Import path.** `PromptFileParser` is imported via `platform/promptFiles/common/promptsService` (a re-export), while `promptsServiceImpl.ts` imports it from `util/vs/.../promptFileParser`. Both work, and the re-export is arguably the better boundary. Just confirm the re-export is meant to be public API.
3. **Possible stale selection.** If a user previously picked an agent that is now hidden, a stored or restored session option could still point to its id. That's probably out of scope, but worth checking that the request path handles an id that isn't in the list (or that the server's 400 error is shown clearly).

## Performance
- `getLocalCustomAgentFiles` now calls `readFile` for each local-only agent, one at a time inside the `for` loop. Agent directories are small and the results go into `_optionsCache` (TTL-based), so the cost is low. Still, collecting the candidates and reading them with `Promise.all` would be easy and avoid serial I/O on slow or remote file systems.
- `localOnly` is only used when `repoIds?.length === 1` (`:1260`), but the scan, and now the file reads, run every time. You could skip the reads, or the whole scan, when that condition is false. That's cheap to add now that the function does more I/O.

## Test coverage
- Seven new cases cover: visibility defaults, a manual-only agent staying visible, the option group being omitted when every agent is hidden, remote vs. local precedence, frontmatter edge cases with and without a remote fetch failure, and deleted or unreadable files.
