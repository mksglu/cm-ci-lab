**Review of PR 23009: local fixtures for outdated listings and cyclic build dependencies**

This PR is already merged. I read the diff and didn't run any tests. Overall it's a sound change that removes network flakiness from four tests, and I found no blocking problems.

**Good**
- `cyclic_build_dependency` now builds its two wheels and the sdist locally and serves them through `FindLinksServer`. It uses `--no-index`, so nothing reaches TestPyPI. It still checks both outcomes: the `--no-binary` build cycle fails, and the plain install succeeds.
- It uses existing helpers (`WheelBuilder`, `write_tar_gz`, `FindLinksServer`, `PackseServer`). It also drops the date-dependent `with_exclude_newer`.
- Renaming the index fixtures to `default.toml` and `extra.toml` and updating every caller is consistent. The new names are generic now that more than pip-compile uses them.
- The `pip_list` tests are gated on `test-python`, not `test-pypi`. That fits, since they need an interpreter but no longer need the network.
- The PR fixed a doc-comment typo ("was a runtime dependency" became "as a runtime dependency").

**Minor points**
1. **Gating:** `PackseServer` is imported under `#[cfg(feature = "test-python")]`, and the tests are gated the same way. This is consistent. The import would only be unused if some non-gated test needed it, and none appears to.
2. **Fixture coupling:** `default.toml` gained `anyio 3.0.0`, `idna 3.6` and `sniffio 1.3.1`, so these now affect every pip-compile test that shares it. The PR says the six resolver tests still pass, which covers this. Any future test that depends on "highest anyio is 4.3.0" or on the exact set of packages in the index is more likely to break now.
3. **Extra index naming:** `list_outdated_index` sets `UV_INDEX_URL` to the default fixture and passes `--index-url` for the extra one. The command-line flag overrides the env var, so it works. Setting the env var is probably only there so the earlier `pip install` step uses the local index. A short comment saying so would help readers.
4. **Fixture coverage:** I couldn't see the end of the diff, which is truncated. Check that `extra.toml` has `anyio 3.5.0`, since the snapshot expects it. The PR description says it does.
5. **Cycle test:** The sdist has only a `pyproject.toml` and no backend module. The build fails because of the cycle, and the snapshot should capture that. If the failure message ever changed to a different error, the snapshot would show it, so this is acceptable.

**Security and performance:** Nothing to flag. The servers are loopback-only, and removing the network calls makes the tests faster and more reliable.

**Verdict:** Looks good. The only suggestion is the small comment from point 3.

For example, `==` or `<` constraints, or `--resolution lowest`, could now pick a different version. The PR says the six resolver tests sharing the fixtures passed, which covers that. Other tests that use this index, if any exist, would need the same check.
