**Review of PR #345293: hide non-user-invocable agents from the Cloud picker**

I read the diff only. I didn't check out the branch or run the tests. The PR is already merged.

**Summary:** The change is small and does what it says. It filters out remote agents with `user_invocable === false`. It still passes the full remote list to `getLocalCustomAgentFiles`, so hidden remote agents can't come back as "missing from remote" warnings. It also parses local-only files' frontmatter with the existing `PromptFileParser`. I found no blocking problems.

**What's good**
- **Filtering and defaults:** Filtering uses `!== false`, so `undefined` stays visible and the default behavior is unchanged.
- **Name matching:** Matching local files against all remote names, not just visible ones, is the key correctness detail. The test "keeps remote visibility authoritative" covers it, including case-insensitive filename matching.
- **Error handling:** The per-file `try/catch` logs and continues. Before this, one bad file would have been caught by the outer `catch` and aborted discovery of the remaining agents.
- **Parser reuse:** Using `PromptFileParser` handles CRLF, trailing YAML comments, nested keys and body-only text correctly. The tests exercise each of these cases.
- **Tests:** The seven cases cover visibility defaults, remote/local matching, API failure, and deleted or unreadable files. The test infrastructure changes are reasonable.

**Minor points (non-blocking)**
1. **Sequential reads (performance):** Each local-only file is now read with `await` inside the loop, so reads happen one at a time. Agent directories are usually small, so this is fine. If it ever matters, `Promise.all` over the unmatched files would work. Only unmatched files are read, which already limits the cost.
2. **Re-reading on every call (performance):** These reads happen each time provider options are computed. Options are likely recomputed on auth, repo and window-focus changes. A cheap cache keyed by URI and mtime could help, but this is probably not worth it yet.
3. **Warning message wording:** The log line `Error reading local agent ...` also fires for parse failures, though `PromptFileParser` rarely throws. Something like "Error processing" would be more accurate. This is a nit.
4. **Silent drops on read failure:** A file that can't be read is omitted from the warning list rather than shown. That seems right, since the warnings are advisory. The log entry keeps it diagnosable.
5. **Test mock shape:** The `FileSystemError` mock hard-codes `code = 'FileNotFound'`. That's fine for the current tests. The "deleted" and "unreadable" cases both end up in the same `catch`, so they test the same path. That's acceptable, but the distinction is cosmetic.
6. **Missing check on the local-only path:** The new `userInvocableAgents.length > 0 || (repoIds?.length === 1 && localOnly.length > 0)` condition is tested for the all-hidden case. I didn't see a test for the repo-count gating when there are several repos. That behavior predates this PR, so it's only a suggestion.

**Security:** I see no concerns. Local file content is only parsed for frontmatter and isn't executed or sent anywhere. The remote filter reduces how many agents a user can select, and the PR notes that selecting one led to an HTTP 400.

**Verdict:** Looks good to me. The tests are thorough for the behavior changed, and the nits above can be left as they are.

# REVIEW B

**Review of PR #345293: hide non-user-invocable agents from the Cloud picker**

The PR is already merged. The change is small, focused and well tested. I found no blocking issues, only a few non-blocking suggestions.

**What it does**
- It filters remote agents with `user_invocable === false` out of the picker. Agents where the field is undefined stay visible, so existing behaviour is kept.
- It still passes the full remote list to `getLocalCustomAgentFiles`. A hidden remote agent therefore can't show up again as a "Missing from remote" warning entry. The comment in the code explains this.
- It parses local-only agent files with the existing `PromptFileParser` and skips files whose frontmatter has `userInvocable === false`. It no longer uses ad-hoc string matching.
- It wraps each file read in its own try/catch, so one bad file is logged and the rest are still discovered.

**Observations and suggestions**
1. **Performance:** `readFile` now runs sequentially (`await` inside the `for` loop) for every local-only file. Directories are usually small, so this is minor. `Promise.all` would remove the serial latency if the picker ever feels slow. It would also change the order of results, unless you map and then filter.
2. **Parser reuse:** `new PromptFileParser()` is created for every file. If the parser holds no state, create it once outside the loop.
3. **Doc comment:** the comment above `getLocalCustomAgentFiles` is updated, but `matches` isn't described. It's worth noting that `matches` is built from all remote names, including hidden ones, because that is the subtle part.
4. **Matching on `localOnly` only:** a local file is parsed only when it has no remote match. A local file that matches a remote agent keeps the remote's visibility, which is the intended behaviour. A test covers it ("keeps remote visibility authoritative").
5. **Decoding:** `new TextDecoder().decode(content)` is fine. If `readFile` can return a `Uint8Array` with a BOM, check that the parser handles it. That is an edge case.
6. **Log level:** `warn` for a deleted file is acceptable. A deleted file in a race is expected noise, so `debug` might suit that case better. The test does assert one warning for both cases, so changing it would need a test update.

**Tests**
- Coverage is good. It includes:
  - visibility defaults
  - manual-only (`disable_model_invocation`) agents staying visible
  - the group being omitted when every agent is hidden
  - case-insensitive matching
  - CRLF line endings and trailing YAML comments
  - body-only and nested `user-invocable` text that must not count
  - an API failure
  - deleted and unreadable files
- The mock setup is somewhat heavy: a `vscode` mock with `FileSystemError`, `asRelativePath` and `window`, plus `observableValue` for the git service. It is reasonable and contained in the spec file.
- One gap: nothing checks the picker when a remote agent is hidden but `repoIds.length !== 1`. That path only affects whether local-only entries show, so it's low risk.

**Security**
- No concerns. File reads are limited to the workspace's `.github/agents`, and the parsed content is only used to read a boolean.

**Verdict:** Approve, which matches the existing review. The suggestions above are optional follow-ups.
