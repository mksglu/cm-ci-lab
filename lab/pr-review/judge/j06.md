# REVIEW A

**Review of PR 37046: distrust compromised eMudhra CAs.** The PR is already merged. I read the diff and did not build or run anything.

**Summary:** This is a security-driven dependency bump with a small code migration. It does four things:
- It raises `rustls-webpki` to 0.103.16, which rejects the compromised eMudhra keys.
- It moves `webpki-roots` and `webpki-root-certs` to 1.0.10, which drops the compromised root.
- It bumps `aws-lc-rs` to 1.18.2, with the ML-DSA imports moved from `unstable::signature` to the stable `signature` module.
- It bumps `deno_graph` to 0.111.1.

**Good**
- The change is minimal and focused. The `Cargo.toml` floor versions (`rustls-webpki = "0.103.16"`) make sure a future lockfile refresh can't regress to a vulnerable version.
- The 0.26.11 `webpki-roots` wrapper is used for reqwest and hyper-rustls, so every consumer ends up on the 1.0.10 bundle. Without it, a stale 0.26.x bundle could stay in the build.
- `to_pkcs8v1()` keeps the existing PKCS#8 export format, so the change is backward compatible. The PR description explains why it was chosen.

**Concerns / suggestions**
1. **Duplicate `aws-lc-sys` (0.40.0 and 0.46.0).** `aws-lc-sys` is still pinned to `0.40.0` in the workspace (with `prebuilt-nasm`), while `aws-lc-rs` 1.18.2 pulls in 0.46.0.
   - Two copies of AWS-LC will be compiled and possibly linked. That increases build time and binary size.
   - It could also cause symbol conflicts. aws-lc-sys uses a versioned symbol prefix, which mitigates this, but it is worth confirming.
   - Check whether `deno_crypto_provider` and `ext/node` genuinely need the direct `aws-lc-sys` dependency. If they do, bump the pin to 0.46.0 and keep `prebuilt-nasm` so there's one copy.
   - Also check that the `prebuilt-nasm` feature applies to 0.46.0 on Windows. The 0.46.0 lockfile entry lists `cc`, `cmake`, `dunce`, `fs_extra` and `pkg-config` as dependencies. That is plausible, but I couldn't verify that Windows builds avoid needing NASM.
2. **Test coverage.** The PR adds no tests. A regression test that a chain through a compromised eMudhra key is rejected would be hard to build, because it needs fixture certificates. Still, a unit test that the root store no longer contains `emSign ECC Root CA - G3` would be cheap and would guard against a downgrade. The ML-DSA export path relies on existing WebCrypto tests, so confirm that the `tests/unit` ML-DSA tests cover the PKCS#8 round-trip byte-for-byte, since `to_pkcs8v1` is the changed piece.
3. **Major-version jump for `webpki-root-certs` (0.26 → 1.0).** The API changed: `TLS_SERVER_ROOT_CERTS` is now a different type. The build apparently passes in CI, but the PR's validation only lists `deno_tls`, `deno_node` and `deno_graph` checks. Reviewers should confirm the full workspace check passed before merge.
4. **PR hygiene.** The PR bundles several things that CLAUDE.md says should stay focused: a security fix, the `aws-lc-rs` and ML-DSA migration, and the `deno_graph` bump. The ML-DSA change is justified because it is needed for the bump. The `deno_graph` bump was appended afterwards, and the description reads as if it were pasted on at the end. Describing the `deno_graph` bump in its own section would make the history clearer.

**Security:** There are no new concerns. The change improves security. The remaining risk is that downstream crates still pinning older webpki versions might keep the compromised root. The `cargo tree -i rustls-webpki` and `cargo tree -i webpki-roots` checks should show only one version of each. The lockfile shows `rustls-webpki` at a single version, which is good.

**Verdict:** Looks good. The most worthwhile follow-up is the duplicate `aws-lc-sys` versions. A small root-store assertion test would also help.

# REVIEW B

**Review of PR 37046: distrust compromised eMudhra CAs** (already merged)

**Summary:** The PR is a dependency bump. It moves `rustls-webpki` to 0.103.16, `webpki-roots` and `webpki-root-certs` to 1.0.10, `aws-lc-rs` to 1.18.2 and `deno_graph` to 0.111.1. It also moves the ML-DSA code onto the stable `aws_lc_rs::signature` API. The security intent is sound, and I found no blocking problems. I only read the diff and did not build or run anything.

**What looks good**
- The `rustls-webpki` floor is now `0.103.16`. That is the right way to make sure the fix is never resolved below the minimum.
- The transitive `webpki-roots 0.26.11` is a thin wrapper over 1.0.10. So reqwest and hyper-rustls get the same root set as the direct dependencies, and the lockfile shows no stale 0.26.1 bundle.
- The ML-DSA change is mechanical: the import paths move out of `unstable`. Using `to_pkcs8v1()` keeps the existing PKCS#8 export format, which is the safe choice. The PR description explains it.

**Concerns and suggestions**
1. **Two `aws-lc-sys` versions.** The lockfile now has 0.46.0 (pulled in by `aws-lc-rs` 1.18.2) and 0.40.0 (pinned in the workspace and used by `deno_crypto_provider` and `deno_crypto`). This means two copies of AWS-LC get compiled and linked.
   - **Build cost:** build time and binary size go up.
   - **Symbol clashes:** the `aws-lc-sys` crates use a `links` key, and Cargo normally allows only one per graph. The graph resolved here, probably because the prebuilt or symbol-prefixed builds differ. That should be confirmed by a clean CI link on every platform, especially Windows with `prebuilt-nasm`, and macOS.
   - **Raw FFI interop:** any code that mixes `aws-lc-rs` types with direct `aws-lc-sys` FFI calls could cross library copies. `ext/crypto` uses both, so check that no pointers or state are shared between them.
   - **Follow-up:** bump the workspace `aws-lc-sys` pin to 0.46 so they unify.
2. **Major version jump for `webpki-roots` and `webpki-root-certs`.** The 0.26 to 1.x move changes the API, notably `TLS_SERVER_ROOTS` and the root-cert types. The PR says the checks passed, but confirm that every user of these crates compiles, including the node TLS root-cert listing (`tls.rootCertificates`). There is no test showing that `emSign ECC Root CA - G3` is gone.
3. **Test coverage.** The PR adds no tests. A spec or unit test would guard against a regression. For example, assert that `tls.rootCertificates` or the bundled roots don't contain `emSign ECC Root CA - G3`. A test that rejects a chain through a compromised key would be heavier but more direct. Since these are pure version bumps, relying on upstream tests is a reasonable trade-off, but a cheap root-list assertion would be worthwhile.
4. **Scope.** The PR mixes the TLS fix, the AWS-LC upgrade with the ML-DSA migration, and the `deno_graph` bump. CLAUDE.md asks for minimal, focused changes. The pieces are related, since the verifier needs the newer AWS-LC, but splitting them would make reverts easier. The `deno_graph` bump also appears to be a separate commit folded in.
5. **Minor.** The `pkg-config` bump from 0.3.30 to 0.3.34 is a lockfile side effect and is fine. `rustls-webpki = "0.103.16"` is a caret requirement, so it is a floor, not a pin. That is fine for a security fix.

**Performance and security:** I see no runtime performance concerns. Security-wise, this closes the trust gap for the eight compromised public keys, including cross-signed paths. The remaining risk is the dual `aws-lc-sys` setup in item 1.

**Verdict:** Approve. The follow-ups are to unify `aws-lc-sys`, and to add a small regression test that the distrusted root is absent.
