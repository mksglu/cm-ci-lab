# REVIEW A

**Review of PR 37046: distrust compromised eMudhra CAs.** The PR is already merged. This is a security-driven dependency bump, and it looks correct. I read the diff only and did not build or run anything.

**What it does**
- Bumps `rustls-webpki` to 0.103.16 and `webpki-roots`/`webpki-root-certs` to 1.0.10, so the compromised eMudhra keys and the `emSign ECC Root CA - G3` root are no longer trusted.
- Moves the transitive `webpki-roots` 0.26 users, reqwest and hyper-rustls, to the 0.26.11 wrapper, which re-exports 1.0.10. Both the direct and transitive consumers therefore get the fixed bundle, and the lockfile shows this.
- Bumps `aws-lc-rs` to 1.18.2 and moves the ML-DSA code from `unstable::signature` to the stable `signature` module.
- Bumps `deno_graph` to 0.111.1, which carries the same TLS fix.

**Points worth checking**
1. **Two `aws-lc-sys` versions in the lockfile.** `aws-lc-rs` now pulls `aws-lc-sys` 0.46.0, while the workspace pins 0.40.0 for `deno_crypto_provider` and `deno_node`. That means two copies of AWS-LC get compiled and linked.
   - Build time and binary size go up.
   - Two copies of the C symbols could clash at link time. `aws-lc-sys` normally prefixes its symbols per version to avoid this, but CI should confirm it.
   - The 0.40.0 pin in `Cargo.toml` could be bumped to line up with 0.46.0. That may be non-trivial, because `deno_crypto_provider` and `deno_node` use the sys crate directly.
   - A follow-up should either unify the versions or record why they differ.
2. **`to_pkcs8()` replaced by `to_pkcs8v1()`.** The PR says this keeps the existing PKCS#8 export format, which is plausible. I saw no test for it in the diff.
   - A round-trip test would catch a silent format change: export an ML-DSA key with `exportKey("pkcs8")`, import it again, and compare the bytes.
   - The existing WebCrypto ML-DSA tests may already cover this. Check that they ran in CI.
3. **Loose version requirement.** `rustls-webpki = "0.103.16"` accepts any later 0.103.x release. That is the right trade-off for a security floor, since it avoids pinning below a future fix. Most other TLS crates here are pinned with `=`, so the style is inconsistent but defensible.
4. **No regression test for the distrusted CA.** None is practical without a test chain signed by the compromised keys, so I would not block on this. A unit test that checks `emSign ECC Root CA - G3` is absent from the bundled roots would still guard against a later dependency downgrade.

**Convention and process**
- The PR adds no changes outside the dependency update and the matching ML-DSA migration, which fits the "minimal changes" rule in CLAUDE.md.
- The description is clear and links the upstream fixes.
- The `deno_graph` bump is unrelated to the main change in the code, but it carries the same TLS fix, so bundling it is reasonable.

**Performance and security**
- There is no runtime cost beyond the larger binary from the second AWS-LC copy.
- The change improves security by removing trust in the compromised CAs and rejecting cross-signed paths through the compromised keys.

**Verdict:** Approve. The two follow-ups I would raise are unifying the `aws-lc-sys` versions and adding a PKCS#8 export regression test.

# Review of PR 37046: distrust compromised eMudhra CAs

**Overall:** Approve. This is a focused security dependency bump and it does what the description says. The PR is already merged, so the points below are follow-ups rather than blockers.

## What it does
- **Verifier:** it raises `rustls-webpki` to 0.103.16, which rejects certificate paths containing the compromised keys. The PR description says this covers cross-signed paths too.
- **Root bundles:** it bumps `webpki-roots` and `webpki-root-certs` to 1.0.10, which removes `emSign ECC Root CA - G3`. Reqwest and hyper-rustls get the same bundle through the 0.26.11 wrapper.
- **AWS-LC:** `aws-lc-rs` goes to 1.18.2. The ML-DSA imports move from `unstable::signature` to the stable `signature` module, and `to_pkcs8()` becomes `to_pkcs8v1()`.
- **`deno_graph`:** it goes to 0.111.1, which carries the same TLS fix.

## Observations

1. **Two `aws-lc-sys` versions in the lockfile (0.46.0 and 0.40.0).** `aws-lc-rs` 1.18.2 pulls in `aws-lc-sys` 0.46.0. `deno_crypto_provider` and `deno_crypto` still pin 0.40.0 through the workspace entry `aws-lc-sys = "0.40.0"`.
   - That means two copies of AWS-LC get compiled and linked. This increases build time and binary size.
   - Both copies export C symbols, so there is a risk of symbol clashes. AWS-LC normally prefixes its symbols per version, which is probably why it links.
   - It is worth confirming that the `prebuilt-nasm` feature is applied consistently on Windows. The 0.46.0 entry in the lockfile lists `cc`, `cmake` and `dunce`, so it builds from source there.
   - A follow-up could bump the workspace `aws-lc-sys` to 0.46 so there is a single copy. This only works if `deno_crypto_provider`'s direct FFI use is compatible.

2. **`to_pkcs8v1()` and export compatibility.** The PR says this keeps the existing PKCS#8 export format, and that is the right call. I would still want a test that checks the exported ML-DSA PKCS#8 bytes against a known fixture. That would catch a format change in any later AWS-LC upgrade. Existing WebCrypto ML-DSA tests probably cover a round trip, but a round trip alone wouldn't catch a format change.

3. **No regression test for the distrust itself.** The PR is a pure dependency change, and a TLS test against a chain through the compromised CAs is hard to build. A cheap alternative is a unit test or spec test that checks `emSign ECC Root CA - G3` is absent from the bundled roots. It would stop a downgrade or a lockfile revert from silently bringing the roots back.

4. **Version pinning style.** `rustls-webpki = "0.103.16"` and `webpki-roots = "1.0.10"` are caret requirements, so they set a minimum rather than an exact version. That fits a security floor and matches the existing style (`rustls` is pinned with `=`, `rustls-webpki` was not). The lockfile enforces the exact version in practice.

5. **Unrelated change bundled in.** The `deno_graph` bump is separate from the TLS and ML-DSA changes. CLAUDE.md asks for minimal PRs. Here it is justified, because `deno_graph` carries the same TLS fix and would otherwise leave the old `webpki-roots` in the tree.

6. **`webpki-roots` 0.26.11 is a wrapper.** The 0.26.x line is now only a re-export of 1.0.10, which is correct. Once reqwest and hyper-rustls move to 1.x, that duplicate entry can go.

## Security
The change reduces risk. The remaining check is to confirm in the built binary that `cargo tree -i webpki-roots` shows only 1.0.10 and the 0.26.11 shim, and that no older `webpki-root-certs` is left in the tree.
