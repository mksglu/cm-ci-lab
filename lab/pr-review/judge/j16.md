# REVIEW A

**Review of PR #36944: assert message functions and printf-style arguments** (already merged, so these are follow-ups)

Overall this is a sound change. It moves message handling into one `innerFail()` helper, which removes duplicated Error/message logic. The `MessageTuple` doc comment and type make the calling convention clear. I only read the diff and did not run any tests.

**Issues**

1. **Commented-out code in `internalMatch`** (`ext/node/polyfills/assert.ts`). Several old lines were commented out instead of deleted: the `ErrorPrototype` check, `const generatedMessage = !message`, `message ||= ...`, `const err = new AssertionError({`, and the `err.generatedMessage` and `throw err` lines. These should be removed.

2. **Possibly unused imports in `assert.ts`.** `ObjectPrototypeIsPrototypeOf` and `ErrorPrototype` may now be unused, since `innerFail` and the `internalMatch` check were their only users. `tools/lint.js --js` should show this.

3. **Behavior change in `internalMatch` for an empty-string message.** `generatedMessage` used to be `!message`, so `""` counted as generated. It is now `message.length === 0`, so `match(s, re, "")` gives `generatedMessage === false`. The `message[0] ||=` line still substitutes the default text, so the message and the flag now disagree. Node's own handling is worth checking here.

4. **`internalMatch` mutates its input array.** `message[0] ||= ...` writes into the rest-args array. That is harmless today, but it is brittle. It would be cleaner to build a new tuple. The `||=` also runs when `message[0]` is a function or Error. Those are truthy, so nothing happens, but it only works by accident.

5. **`compareExceptionKey` passes `[message]` unconditionally.** If `message` can be `undefined`, `innerFail` takes the final `else` branch and throws `ERR_INVALID_ARG_TYPE` instead of using the default message. Check whether callers always pass a string there. If not, use `message === undefined ? [] : [message]`.

6. **`innerOk` ignores trailing arguments when `args[1] == null`.** For example, `assert(false, undefined, "x")` is silently accepted. This is probably what Node does, but it is worth confirming.

7. **Swallowed errors in message functions.** Silently catching exceptions from a user-supplied message function matches the stated Node behavior. A comment pointing at the Node source would help future readers.

**Tests**
- The change relies only on enabling `parallel/test-assert.js` in `tests/node_compat/config.jsonc`. That is reasonable.
- A small spec or unit test would still help with the edge cases above, particularly `generatedMessage` for `match`/`doesNotMatch` and trailing arguments after an Error or function.

**Performance and security**
- No concerns. The only cost is a small array allocation per assertion call, and `format` runs only when there are extra arguments.

# REVIEW B

**Review of PR #36944: assert message functions and printf-style arguments** (already merged, with approval from bartlomieju)

Overall this is a clean refactor. Moving message handling into `innerFail` removes duplicated Error-passthrough logic and matches Node's design. I found a few issues, none of them blocking.

**Code quality**
- `internalMatch` in `assert.ts` still has commented-out old code: the `ObjectPrototypeIsPrototypeOf` block, `const err = new AssertionError`, and `err.generatedMessage`. Delete it. This also probably leaves `ErrorPrototype` and `ObjectPrototypeIsPrototypeOf` unused in `assert.ts` if nothing else references them, and the lint may flag that.
- `message[0] ||= ...` in `internalMatch` mutates the rest-args array. That's fine here, because the array is local. It's subtle, though: with `match(s, re, "")`, `generatedMessage` is false but the empty string is replaced by the default message. Node does roughly the same, so this is OK, but a comment would help.
- The `MessageTuple` doc comment says "print like substitutions". "printf-style" is clearer.
- `ErrorPrototypeToString` and `ArrayPrototypeSlice` are destructured from primordials, which is correct. Check that `ErrorPrototypeToString` actually exists in the primordials. It does in deno_core's list, as far as I recall.

**Potential bugs**
- In `innerOk`, `args[1] == null` takes the generated-message path. The old code did the same (`message == null`). But with `assert.ok(false, undefined, "x")`, trailing args are silently dropped. Node behaves the same, so this is fine.
- A function message that throws is swallowed silently. This is documented as intentional and matches Node.
- A function message that returns a non-string falls back to the default message. The default message here is the `AssertionError` auto-generated one, not the `getErrMessage` source text. For `assert.ok(false, () => 1)` the result is therefore a diff-style "false == true" message. Verify this against Node 26. I believe it matches, since Node also passes `undefined`.
- `generatedMessage` for `internalMatch` is computed before the `||=` assignment, so it's correct. For `innerFail` calls with a message tuple but no `generatedMessage`, the `AssertionError` constructor sets it, which is fine.
- `compareExceptionKey` wraps `message` as `[message]`. If `message` is `undefined` (when the user passed no message), this gives `[undefined]`. `typeof undefined` is neither string, Error nor function, so it would throw `ERR_INVALID_ARG_TYPE`. Check the call sites. The `expectsError` and `expectsNoError` paths always pass strings, but `compareExceptionKey` may receive an undefined `message`. If it can, that's a regression, so please confirm. The `test-assert.js` pass suggests the common paths are covered.
- `partialDeepStrictEqual`, `equal` and the other comparison functions now take `...message`. Their bodies (not shown in the diff) must pass `message` through to `innerFail` as an array. Since they pass, they presumably do.

**Performance**
- Rest args allocate an array per call, even on the success path of `strictEqual` and similar. That is negligible next to the comparison itself, but `assert.ok` is hot in some test suites. `innerOk` was already spreading via `SafeArrayIterator`, so there's no new cost there. `ArrayPrototypeSlice` only runs on failure.

**Security**
- No concerns. A user-supplied message function is called only on failure, and exceptions are contained. `format` with user arguments is the same as `util.format`.

**Test coverage**
- The only coverage is un-ignoring the upstream `parallel/test-assert.js` in `tests/node_compat/config.jsonc`. That's reasonable for a compat fix. I'd still add a small spec or unit test for the Deno-specific edge cases:
  - function message returning a non-string
  - function message that throws
  - trailing args after an `Error` or function, which should give `ERR_AMBIGUOUS_ARGUMENT`
  - `assert.match` with a printf message
  - a non-string, non-function message, which should give `ERR_INVALID_ARG_TYPE`
- Other upstream assert tests are already enabled and unaffected.

**Conventions**
- The PR follows the repo's guidance: a small, focused change with no drive-by edits. The PR description is clear and discloses AI use.
- Cleanup follow-up: remove the commented-out code in `internalMatch`, and confirm that `tools/lint.js --js` is clean (unused imports).
