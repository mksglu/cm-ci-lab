## Review of #23017: Preserve inline comments when updating an existing dependency group

### Summary
Before this change, `add_dependency_group_requirement` and `ensure_dependency_group` always called `InlineTable::fmt()` on an inline `dependency-groups` table. That call wipes the decor (comments and whitespace) between keys. Now `fmt()` runs, and keys are sorted, only when a group is actually inserted. The fix is small and correct, and the scope is reasonable.

### Correctness
- **Making the sort conditional changes nothing.** Before, `sort_values()` also ran when an existing group was updated. Adding to an existing array never changes key order, though, so if `was_sorted` was true the sort did nothing. Limiting it to `new_group` is safe.
- **The early return in `ensure_dependency_group` matches the old behaviour.** When the group already exists, the function previously did nothing except call `fmt()`. Returning early skips only that call, which is the point of the PR.
- **Comments are still lost when a group is inserted.** Something like `uv add --group release2 …` against the TOML in the PR description will still run `fmt()` and remove `# Local development` and `# Release tests run separately.` The PR description is honest that only the existing-group case is fixed. Still, the old comment ("you can't put comments between items in an inline table anyway") was wrong once multi-line inline tables with comments are allowed, and it has simply been deleted. A short note saying insertion still reformats and drops comments would help the next reader. Better still would be to insert the key without calling `fmt()` on the whole table and only set decor for the new key.
- **Single-line inline tables are no longer normalized.** For example, `dependency-groups = {dev=[]}` used to come out as `{ dev = [...] }` after an add, and now the outer spacing is kept as written. That fits the "minimise churn" approach elsewhere in this file and no existing snapshot changed, so I think it's fine. It's worth knowing about, though.

### Consistency
- **`optional-dependencies` has the same problem and isn't fixed.** `add_optional_dependency` (around line 542) and `ensure_optional_dependency` (around line 584) still call `fmt()` every time, with the same outdated comment. So `uv add --optional dev …` against a commented multi-line `optional-dependencies = { … }` will still drop comments. Either apply the same `new_group` guard there, or say in the PR description that it's left for a follow-up. Otherwise the two code paths now behave differently for no visible reason.
- **Small duplication.** The "insert, sort if it was sorted, then `fmt()` if inline" block now appears twice in nearly the same form, and four times if optional-dependencies is fixed too. A small private helper would keep the paths aligned. That's optional.

### Tests
- The new test `add_dev_preserves_inline_group_comments` follows the nearby style: `uv_snapshot!` for the command, `assert_snapshot!` on `context.read(...)`, and `--frozen`. It covers the case being fixed.
- **The output in the snapshot is awkward:**
  ```toml
  dependency-groups = {
      dev = [
      "ok==1.0.0",
  ], # Local development
  ```
  `reformat_array_multiline` indents relative to column 0 rather than the key's nesting level. This probably isn't new, since the old outer `fmt()` didn't re-indent nested arrays either. It's now locked into a snapshot, so a follow-up issue might be worthwhile.
- **Missing coverage:**
  - Insertion into a commented inline table (for example `--group new`). A snapshot would document the remaining limitation and catch regressions if it's improved later.
  - The `ensure_dependency_group` path, which `uv add --group foo` reaches when there are no requirements, or `uv init`-style flows. Only `add_dependency_group_requirement` is exercised.
- A one-line doc comment on the test explaining the regression would follow the AGENTS.md guidance on non-obvious scenarios. The test name is fairly self-explanatory, so this is minor.

### Performance and security
Neither is affected. The change only skips work.

### Verdict
The fix is correct and low-risk. Before or soon after merging, I'd suggest:
1. Applying the same guard to the `optional-dependencies` paths, or noting that they're deferred.
2. Adding a test (or a code comment) for the insertion case, where comments are still dropped.

# Review: PR #23017, "Preserve inline comments when updating an existing dependency group"

## Summary
When `dependency-groups` is an inline table, `add_dependency_group_requirement` used to call `InlineTable::fmt()` after every edit. That call clears the decor on each key and value, so comments inside a multi-line inline table were lost. The PR now sorts and formats the table only when a group is inserted. Existing groups are updated in place.

It also changes `ensure_dependency_group` to return early when the group already exists. Before, it called `fmt()` even when nothing had changed.

The change is small and the fix is correct for the scenario it targets. It also cuts churn in a second way: a compact table like `dependency-groups = {dev=[]}` is no longer rewritten with normalized spacing when you add to `dev`.

## Correctness / potential issues

1. **The fix only covers updates; inserting a group still loses comments.** With the same fixture, `uv add --group lint foo` takes the `new_group` path. It calls `fmt()` and drops `# Local development` and `# Release tests run separately.` The same happens with `ensure_dependency_group` (e.g. `uv add --group lint` with no packages, or `--script`/workspace paths that reach `add.rs:715`).
   - The PR also deleted the old comment saying "you can't put comments between items in an inline table anyway", correctly, since TOML 1.1 allows it. That makes the remaining `fmt()` calls the same bug on a different path.
   - Possible fix: style only the newly inserted key/value (give it the leading/trailing space decor that `fmt` would apply) instead of formatting the whole table. Or at least add a test that pins down the current insert behavior so the limitation is visible.

2. **The new snapshot shows the inner array badly indented:**
   ```toml
   dependency-groups = {
       dev = [
       "ok==1.0.0",
   ], # Local development
   ```
   The element and the closing `]` don't line up with the `dev` key. The multi-line array formatting in `add_dependency` assumes the array sits at top-level indentation. This isn't a regression, but the snapshot now locks it in. It's worth a follow-up, or at least a sentence in the PR description saying this layout is accepted for now.

3. **Sorting is now skipped for existing groups.** That's fine: if the keys were already sorted and no key was added, `sort_values()` did nothing. Behavior is unchanged.

## Code quality
- **Duplicated insert logic.** `add_dependency_group_requirement` and `ensure_dependency_group` now repeat the same steps: compute `was_sorted`, insert, sort if it was sorted, re-borrow `self.doc` to `fmt()` the inline table. A small private helper, e.g. `fn insert_dependency_group(&mut self, group) -> Result<&mut Array, Error>`, would keep the two from drifting. It would also mean a fix for point 1 only has to land in one place.
- In `ensure_dependency_group`, the old explanatory comments ("To avoid churn … only sort if the existing keys were sorted") were removed rather than moved. The reason the sort is conditional isn't obvious, so it's worth keeping that comment next to `if was_sorted`. The same comment was also dropped from `add_dependency_group_requirement`.
- `let new_group = existing_group.is_none();` is clear. The new comment ("Only inserting a key changes the table layout…") explains why, which matches the repo's comment guidelines.

## Tests
- `add_dev_preserves_inline_group_comments` follows the file's conventions (`uv_snapshot!` plus `assert_snapshot!` of `context.read("pyproject.toml")`) and uses `--frozen`, so it needs no network or index. No `cfg(feature = "test-…")` gate is needed.
- Missing coverage:
  - Adding a **new** group to an inline table that has comments (point 1). It should either assert the comments survive or document that they don't.
  - A single-line inline table with an existing group, e.g. `dependency-groups = { dev = [] }`. Its output changed (no `fmt()` normalization any more) and no existing test covers it; a grep of `crates/uv/tests` finds only this new test using `dependency-groups = {`.
- Optional: a short doc comment on the test explaining the regression (comments between inline-table keys were cleared by reformatting), as AGENTS.md suggests for non-obvious scenarios.

## Performance / security
Nothing to flag. Skipping `sort_values()`/`fmt()` on updates is marginally cheaper.

## Verdict
The fix is good and well scoped for updates. Before calling the issue fully solved, I'd ask for (a) the same treatment, or at least a test, for the group-insert path, (b) a shared helper for the insert logic, and (c) a follow-up for the misaligned array indentation that the snapshot now locks in.
