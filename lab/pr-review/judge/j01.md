# REVIEW A

**Review of PR 23009: use local fixtures for outdated listings and cyclic build dependencies**

The PR is already merged. I read the diff only and did not run the tests.

**What it does**
- It replaces TestPyPI network calls in `list_outdated_columns`, `list_outdated_json` and `list_outdated_index` with local `PackseServer` indexes.
- It rewrites `cyclic_build_dependency` to build two wheels and an sdist locally and serve them through `FindLinksServer`.
- It renames the shared index fixtures from `pip-compile-default.toml` and `pip-compile-extra.toml` to `default.toml` and `extra.toml`.

**Good**
- The change removes network flakiness, which was the cause of the failing CI job. The cycle check and the successful wheel install in `cyclic_build_dependency` are both kept.
- Fixtures are set up explicitly in each test, and the tests follow the style of the existing ones. That matches AGENTS.md.
- The doc comment typo is fixed ("was a runtime dependency" is now "as a runtime dependency").
- The fixtures are renamed and reused instead of duplicated.

**Issues and suggestions**
1. **Feature gates.**
   - The `PackseServer` import and the three list tests are gated on `test-python`, not `test-pypi`. That is consistent, since `test_context!("3.12")` needs a managed interpreter.
   - I couldn't confirm that `cyclic_build_dependency` has the right gate. It builds a wheel with `circular_two` as the build backend and needs a Python 3.13 interpreter. Check that its existing gate, if any, is unchanged, and that `WheelBuilder`, `write_tar_gz`, `FindLinksServer`, `File` and `fs` are imported without gate mismatches. A build with `--no-default-features` would confirm this.
2. **Fixture coupling.** `default.toml` now carries `anyio` 3.0.0, `idna` and `sniffio`, which only the list tests need. The `pip compile` tests share that file, so adding versions could change their resolutions, for example anything that picks the highest `anyio`. The PR says the six resolver tests pass, which covers this for now. A comment in the TOML would help future editors.
3. **`list_outdated_index`.** The context uses `UV_INDEX_URL` while the test also passes `--index-url` on the command line. This is intentional and matches the "default 4.3.0 vs override 3.5.0" description. A short comment would make clear that the env var provides the install index and the flag provides the "latest" lookup index.
4. **Test content.** The `circular-one` sdist has a `pyproject.toml` whose `build-backend = "circular_two"` has no real backend module in the wheel. The expected failure is the recursive-build error, so this works. If the failure ever changes to a different error, the snapshot will catch it.
5. **Style.** The `.parse()?` calls on package names and versions are fine because the test returns `Result`. There are no `unwrap` calls, so it follows AGENTS.md.

**Security and performance**
- There are no security concerns. Everything is loopback and the content is test-only. Local servers also make the tests faster and more deterministic.

**Verdict:** This is a good change. I have only minor suggestions, mainly to verify the feature gates and to document the shared-fixture coupling.

# REVIEW B

**Review of PR 23009: use local fixtures for outdated listings and cyclic build dependencies**

I reviewed the diff only and didn't run any tests. The PR is already merged. It looks good overall: it replaces flaky network access to TestPyPI and PyPI with loopback fixtures, which is the right fix for the CI failure it links to.

**What works well**
- `cyclic_build_dependency` now builds two wheels and an sdist locally. It uses `--no-index --find-links`, so the cycle check no longer depends on `hatchling` being fetched.
- The test also fixes the doc comment typo ("was a runtime dependency" is now "as a runtime dependency").
- The renamed fixtures `indexes/default.toml` and `indexes/extra.toml` are more generic. The `pip_compile.rs` call sites are updated consistently.
- The new `anyio` 3.0.0 entry, with `idna` and `sniffio`, gives the `list_outdated_*` tests a resolvable install. The existing snapshots stay unchanged.

**Issues and suggestions**
1. **Feature gate change.** The listing tests move from `test-pypi` to `test-python`. That is correct, since they no longer need the network. The `PackseServer` import is gated the same way, so there should be no unused-import warning. Please check that `cargo clippy` is clean with `test-python` both on and off. In `pip_install.rs`, `WheelBuilder`, `FindLinksServer` and `write_tar_gz` must already be imported unconditionally. I couldn't see those imports in the diff.
2. **Shared fixture coupling.** `default.toml` and `extra.toml` are now used by both `pip_compile` and `pip_list` tests. Adding `anyio` 3.0.0 and its dependencies to the default index could change results in the existing compile tests that use it. The PR says the six resolver tests passed, which covers this. A short comment in the TOML files noting that they are shared across test modules would help future editors.
3. **Name collision risk.** The index `name` values changed to `default-index` and `extra-index`. These are generic, so check that nothing else keys on the old `pip-compile-*` names, for example snapshot filters or docs. A `grep` for `pip-compile-default` and `pip-compile-extra` would confirm.
4. **Style in `list_outdated_index`.** The context builder line (`test_context!("3.12").with_env(EnvVars::UV_INDEX_URL, ...)`) is formatted differently from the other two tests, which wrap it. This is probably just `rustfmt` output. The test also sets `UV_INDEX_URL` while passing `--index-url` on the command line. That is fine, because it exercises the override, but a one-line comment would make the intent clear.
5. **Test robustness.** `cyclic_build_dependency` relies on the sdist's `build-backend = "circular_two"` resolving to the wheel built by `WheelBuilder`. This works only if the builder produces a module with that name. The PR says the test passes, so it does. Asserting the failure reason in the first snapshot, which already exists, is enough coverage.

**Security and performance**
- There are no security concerns. The servers bind to loopback only, and the PR says socket tracing confirmed that.
- Performance should improve, because the tests no longer make network round-trips.

**Verdict:** The change is sound. The follow-ups are minor: check for stale references to the old fixture names, and add a note that the fixtures are shared.
