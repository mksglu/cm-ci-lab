# REVIEW A

# Review of PR #345293: "chat: hide non-user-invocable agents from the Cloud picker"

**Verdict: approve.** The fix is small and focused, and the tests are good. I found no blocking issues, only the follow-ups and nits below. (The PR is already merged.)

## What it does
- Remote agents with `user_invocable: false` are filtered out of the Cloud custom-agent picker. A missing value still means visible, and `disable_model_invocation` doesn't affect it.
- Local files in `.github/agents/` are still matched against the **full** set of remote names. So an agent hidden remotely can't come back as a "Missing from …" warning just because a local copy exists. This is a nice catch.
- Local-only files are now parsed with the shared `PromptFileParser`, and their `user-invocable: false` frontmatter is respected.

## Code quality
- Reusing `PromptFileParser` instead of a hand-written frontmatter regex is the right choice. The CRLF, inline comment, body-only and nested-key test cases show why.
- Filtering once into `userInvocableAgents` makes the "should we show the group?" check simpler.
- The doc comment on `getLocalCustomAgentFiles` was updated to match.

## Possible bugs and edge cases
1. **Hidden agents can still reach `createSession` by other routes.** The PR only filters the options shown in the picker. `sessionCustomAgentMap` is filled without validation from:
   - `provideHandleOptionsChange` (`copilotCloudSessionsProvider.ts:1434`)
   - `initialSessionOptions` (`:2448`), for example on delegation or a restored session

   Either path can pass a hidden agent's name to `createSession` (`:2763`), which brings back the HTTP 400 from the report. A follow-up could check the selected agent against the user-invocable list (or fall back to `DEFAULT_CUSTOM_AGENT_ID`) before sending the request.
2. **Unreadable local files used to show up and now don't.** Before, a local-only file appeared as a warning entry whether or not it could be read. Now a read or parse failure drops it and logs a warning. That's a reasonable call, but it is a change in behaviour; a sentence in the code comment would help.
3. **Noisy warning on a delete race.** The outer `catch` quietly ignores `FileSystemError` with code `FileNotFound` for the directory. The new per-file `catch` logs `warn` even for that case, i.e. a file deleted between `readDirectory` and `readFile`. You could ignore it (or log at `trace`) to match the outer handler. The "deleted" test currently expects a warning, so it would need updating too.
4. **The local file is not checked when a remote agent exists.** If a remote agent is visible but the local file says `user-invocable: false`, the agent stays visible. That's intended ("remote visibility authoritative") and tested, so this is only a note.

## Performance
- `readFile` and parse now run one at a time for each local-only file, every time `provideChatSessionProviderOptions` is called. Agent folders are small, so the cost is minor. If you want to tidy it, map the local-only candidates to promises and await them with `Promise.all` (or `Promise.allSettled`, since one failure must not drop the rest).
- Files that match a remote agent are correctly not read.

## Security
- Nothing new. Files are read only from the first workspace folder's `.github/agents`, and the content is only parsed for frontmatter. Hiding agents in the UI is not an authorization boundary, so the server should keep enforcing `user_invocable` itself.
