# REVIEW A

**Review of PR #36944: assert message functions and printf-style arguments** (already merged)

**Overall:** This is a sound change. Moving message handling into a single `innerFail()` removes duplicated logic, and the `MessageTuple` type documents the contract well. Un-ignoring `parallel/test-assert.js` is the right test signal. I found a few issues, none blocking.

**Issues and suggestions**

1. **Leftover commented-out code** in `internalMatch` (`assert.ts`). The old `ObjectPrototypeIsPrototypeOf(ErrorPrototype, message)` check, `const err = new AssertionError(...)`, `err.generatedMessage` and `throw err` are all commented out instead of deleted. Delete them. If `ObjectPrototypeIsPrototypeOf` and `ErrorPrototype` are now unused in `assert.ts`, `tools/lint.js --js` may flag them, so check that too.

2. **`internalMatch` mutates the caller's `message` array** with `message[0] ||= ...`.
   - This works because the array is a fresh rest parameter.
   - It does not give the "use default" meaning for `message = [""]` or `[undefined]`. The `||=` replaces a falsy first element with the default string, but the `generatedMessage` flag is only true when `message.length === 0`. So `match("x", /y/, "")` gives the default text but reports `generatedMessage: false`. Node computes this from `!message`. Compute `generatedMessage` from `!message[0]` to match.
   - The same path also handles a message function or Error. Because `||=` only fires for falsy values, a function or Error passes through unchanged, which is correct.
   - A non-string `string` argument, such as `match(1, /x/)`, takes the default-message path and still goes through `innerFail` correctly.

3. **Semantics of a missing source in `innerOk`.** Falling back to `[]` when `getErrMessage` returns `undefined` is sensible. It keeps `generatedMessage = true` with the default `AssertionError` text. A short test would pin this down.

4. **Empty-string message behavior in `innerOk`.** With `args[1] == null`, `assert(false, undefined)` is treated as generated, which matches the old behavior. `assert(false, "")` now goes through `innerFail` with `[""]`, resolves to `""`, and `AssertionError` receives an empty message. The old code did the same, so there is no regression. Confirm it matches Node 26.

5. **`format(...)` with a single string argument.** The code skips `format` when `message.length === 1`, so `%%` is not collapsed. Node does the same, so this is fine.

6. **Function message that throws.** The `catch {}` swallows errors silently. That matches the stated Node 26 behavior and the PR description, but add a comment noting it is intentional (the existing comment is adequate).

7. **Arity handling.**
   - The `arguments.length < 2` checks still work with rest params.
   - `rejects`, `doesNotReject`, `throws` and `doesNotThrow` (the `expectsError` and `expectsNoError` paths) wrap messages as `[message]`, so those still accept a single message only. Node also supports function and format arguments there. That is reasonable scope for a PR that "fixes part of #35293", but note it in the issue.
   - `compareExceptionKey` wraps `message` as `[message]`. If `message` is `undefined`, this becomes `[undefined]`, which hits the `ERR_INVALID_ARG_TYPE` branch. It needs a check. Look at how `compareExceptionKey` is called, and whether `message` can be undefined there. If it can, this is a real bug.
   - The same concern applies to `expectsError`/`expectsNoError` when the caller passes `message` through. The new code builds the message string itself, so those are fine.

8. **Performance.** Rest parameters on every comparison call allocate an array. This is minor for assertions, and the cost is only paid on the failure path in `innerFail`. `innerOk` now uses `...args` and `ArrayPrototypeSlice` only when the assertion fails, so the passing path is cheap.

9. **Tests.** Coverage rests entirely on the upstream Node test, `parallel/test-assert.js`. I'd like to see a small spec or unit test for the Deno-specific deviations: the `innerOk` fallback when the source is unavailable, and the `generatedMessage` flag for `match`. That is optional given the node_compat coverage.

**Security:** No concerns. Message functions are user-supplied and called inside try/catch.

**Verdict:** Approve, with a follow-up PR to remove the dead commented code, fix `generatedMessage` for empty-string messages in `match`, and verify the `compareExceptionKey` `undefined` message case.

# REVIEW B

**Review of PR #36944: assert message functions and printf-style formatting**

The PR is already merged and approved. The design is sound: it moves message handling into one `innerFail`, and the `MessageTuple` type is a clear way to pass the message arguments. I read the diff only. I didn't build it or run any tests.

**Issues and suggestions**

1. **Commented-out code in `internalMatch`.** `ext/node/polyfills/assert.ts` still has dead lines such as `// if (ObjectPrototypeIsPrototypeOf(ErrorPrototype, message))`, `// const err = new AssertionError({` and `// throw err;`. They should be deleted. Check that `ErrorPrototype` and `ObjectPrototypeIsPrototypeOf` are still used elsewhere in the file, otherwise they are now unused destructured imports and will trip lint.

2. **`message[0] ||= ...` in `internalMatch`.**
   - It mutates the caller's rest array.
   - If the user passes `""` or another falsy value as the first argument, `generatedMessage` is `false` (the length is 1) but the message is replaced with the default text. The `generatedMessage` flag is then wrong. Node has similar quirks, so this is minor.
   - If the first argument is falsy and isn't a string, such as `0` or `null`, it is silently replaced instead of raising `ERR_INVALID_ARG_TYPE`.
   - If the first argument is a function or `Error`, `||=` leaves it alone, which is correct.
   - An `Error` argument now goes through `innerFail` and is thrown, which preserves the old behavior.

3. **Trailing arguments in `innerOk`.** `args.length === 1 || args[1] == null` treats `assert(false, undefined, "x")` as a generated message and drops the trailing argument. This probably matches Node, but it is a subtle case worth a test.

4. **`generatedMessage` for `compareExceptionKey` and `expectsError`.** These now pass `[message]` and rely on `AssertionError` to set `generatedMessage`. Before, they passed a plain string, so behavior should be unchanged. I'm assuming a non-`undefined` message gives `generatedMessage === false`, as it did before.

5. **Function messages that throw.** A message function that throws is swallowed with a bare `catch {}`. That matches the stated Node behavior. The comment is good.

6. **Printf formatting with one argument.** `message.length > 1 ? format(...) : message[0]` correctly avoids `%%` processing on a lone string. Node behaves the same way.

7. **Type annotations.** `message[0](obj.actual, obj.expected)` and the `as MessageTuple` cast rely on narrowing. Check that `deno check` and lint pass on this polyfill.

8. **Unrelated churn.** Reformatting the `getErrorSourceExpression` destructuring is a drive-by change. CLAUDE.md asks for minimal diffs.

**Test coverage**

- The only test change is un-ignoring `parallel/test-assert.js` in `tests/node_compat/config.jsonc`. That is the upstream Node test, so it covers the new behavior well, though the author says it was run only on a local debug build.
- A small spec or unit test for the Deno-specific edge cases would help, mainly the function message that throws, the trailing-argument errors, and `assert.match` with a message function.

**Performance and security**

- Performance is not a concern. Rest arrays are allocated only on the assertion path, and `innerOk` on the success path just spreads its arguments.
- There are no security concerns.

**Verdict:** Good change. The main follow-up is cleaning up the commented-out code in `internalMatch`, ideally with a short fix-up PR.
