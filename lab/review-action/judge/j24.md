# REVIEW A

**Review of PR 23009: local fixtures for outdated listings and cyclic build dependencies**

The PR is already merged. Overall it's a sound change that removes a flaky network dependency (the TestPyPI 503). I found no blocking issues. I only read the diff and did not run the tests.

**What's good**
- The `cyclic_build_dependency` test is now hermetic. It serves wheels and an sdist through `FindLinksServer`, and it still covers both the recursive-build failure and the wheel-install success.
- It also fixes a doc comment typo ("was a runtime dependency" is now "as a runtime dependency").
- `--no-index` with `--find-links` makes sure nothing leaks to the network.
- Renaming `pip-compile-default.toml` and `pip-compile-extra.toml` to `default.toml` and `extra.toml` fits their wider use. All call sites in `pip_compile.rs` were updated.
- The new tests use explicit setup, with no loops or `allow_duplicates!`. That matches AGENTS.md.

**Points to check**
1. **Feature gating.**
   - `cyclic_build_dependency` has no `#[cfg(feature = ...)]` gate. It builds with Python 3.13, so it may need `test-python`, or a more specific gate such as `test-python-managed`, depending on how `test_context!("3.13")` is gated elsewhere in that file.
   - The list tests moved from `test-pypi` to `test-python`. The PR says they pass with only `test-python` enabled.
   - The `PackseServer` import is gated with `#[cfg(feature = "test-python")]`. That's consistent, but any other test in `pip_list.rs` that uses it needs the same gate.
2. **Index naming.** The `name` field in the renamed scenario files changed to `default-index` and `extra-index`. This differs from the earlier `pip-compile-*` pattern. It's harmless unless something keys off the name, such as snapshot paths or a generated index path. The PR says the six resolver tests passed, which suggests nothing does.
3. **Test setup differs between tests.** In `list_outdated_columns` and `list_outdated_json`, the index is set through `UV_DEFAULT_INDEX`. In `list_outdated_index`, it's set through `UV_INDEX_URL`. The latter may be intentional, because that test passes `--index-url` on the command line. A short comment would help readers see why they differ.
4. **Unwrap-free code.** The `"0.2.0".parse()?` calls and the `Result` return follow AGENTS.md. The `version` variable is cloned or borrowed correctly.
5. **Shared fixture growth.**
   - `default.toml` gained `anyio` 3.0.0 (requiring `idna` and `sniffio`), `idna` 3.6 and `sniffio` 1.3.1.
   - The pip-compile tests that share this fixture could now resolve differently if they touch `anyio`, `idna` or `sniffio` with ranges.
   - The PR reports six resolver tests passed, which covers this. Keep it in mind when changing the fixture later.
6. **Minor.** The sdist in `cyclic_build_dependency` is a minimal `pyproject.toml` with `build-backend = "circular_two"`. The failure snapshot depends on this recursion error message, so it's worth confirming the snapshot isn't brittle against wording changes. That's a nit.

**Performance and security**
- Performance: starting extra local servers adds negligible time, and removing network round trips should make the tests faster.
- Security: nothing concerning. The servers are bound to loopback, and the PR reports socket tracing showed only loopback connections.

**Verdict:** approve. The only follow-up I'd suggest is to double-check the feature gate on `cyclic_build_dependency`.

**Review of PR 23009: use local fixtures for outdated listings and cyclic build dependencies**

This PR is already merged. Overall it is a sound change: it removes two flaky network dependencies (TestPyPI and PyPI) from tests and keeps the snapshots meaningful.

**What's good**
- `cyclic_build_dependency` is now hermetic. The sdist's build-system requires `circular-two`, which depends on `circular-one`, so the cycle still triggers. The second invocation installs from the wheel.
- The test also fixes the doc comment typo ("was a runtime dependency" is now "as a runtime dependency").

- The fixture renames (`pip-compile-default` to `default`, and likewise for extra) are mechanical, and every caller was updated.

**Issues and suggestions**
1. **Possible compile failure without `test-python`.** `PackseServer` is imported under `#[cfg(feature = "test-python")]`. The `cyclic_build_dependency` test is ungated and uses `WheelBuilder`, `write_tar_gz` and `FindLinksServer`. I couldn't see their imports in the diff, so I assumed they are already imported ungated. Confirm that `cargo test --no-default-features` still builds.
2. **Shared fixture coupling.** `default.toml` and `extra.toml` now serve both pip-compile and pip-list tests. Adding `anyio` 3.0.0 plus `idna` and `sniffio` to the default index could change the output of the six compile tests that share it. The PR says those passed, but a short comment in the TOML files saying they are shared would help future editors.
3. **Overlapping tests.** `list_outdated_columns` and `list_outdated_json` now use identical setup. That is fine, since they cover different output formats. Nothing else in the PR duplicates existing coverage.
4. **Minor: `list_outdated_index` mixes mechanisms.** It sets the default via the `UV_INDEX_URL` env var and overrides it with `--index-url`. The other two tests use `UV_DEFAULT_INDEX`. This does exercise CLI-over-env precedence, but it is inconsistent, so a one-line comment would help. Using `UV_DEFAULT_INDEX` in all three would also make them uniform.
5. **Idna and sniffio versions.** The fixture pins `idna` 3.6 and `sniffio` 1.3.1. These are only dependencies of `anyio` 3.0.0 and don't appear in the outdated output. That is acceptable, but note that `list_outdated_*` relies on `pip install` resolving them from the same index.

**Performance and security**
- Local loopback servers make the tests faster and more reliable, and they remove outbound network use in CI. I see no security concerns.

**Verdict:** the change looks good. I'd only double-check item 1 and consider adding the comments from items 2 and 4.
