# REVIEW A

**Review of PR #345293: chat: hide non-user-invocable agents from the Cloud picker**

The PR is small and well scoped, and the change is correct. The PR description says clearly what it fixes and what it leaves to #331475 and #321765. The tests are good. I found no blocking issues, only the suggestions below.

### Correctness

- **Hidden remote agents can't come back as local-only entries.** The full remote list goes into `getLocalCustomAgentFiles`, and the `user_invocable !== false` filter only runs on the picker items. So a local `hidden.agent.md` still matches the remote `hidden` agent and doesn't show up as a "Missing from …" warning. The comment at `copilotCloudSessionsProvider.ts:1255` explains why, and the test `keeps remote visibility authoritative when matching local files` covers it.
- **Default visibility is kept.** The checks are `!== false` (remote) and `=== false` (local), so a missing field still means the agent is visible. Agents with `disable_model_invocation: true` also stay visible, which is correct: that flag only blocks model invocation, not user selection.
- **Only local-only files get read.** Files that match a remote name skip the read and parse entirely. That saves I/O and keeps the remote setting authoritative.
- **Frontmatter parsing reuses `PromptFileParser`** instead of a hand-written regex. The tests check CRLF, trailing comments, `user-invocable` text in the body, and nested keys, so this matches how the rest of the product reads frontmatter.

### Possible issues and suggestions

1. **A saved selection may now point to a hidden agent.** If a user picked a now-hidden agent in an earlier session, and that choice was saved (session options or last-used agent), the picker no longer lists it. Check what happens on the next delegation: does it fall back to `DEFAULT_CUSTOM_AGENT_ID`, or does it still send the hidden agent name and get the same HTTP 400 this PR is fixing? A guard where the selected agent is resolved would make the fix complete.

2. **A deleted file is logged as a warning.** The new inner `catch` logs every failure with `warn`, including `FileSystemError` with code `FileNotFound`. That error can happen through an ordinary race: a file is deleted between `readDirectory` and `readFile`. The outer `catch` already treats `FileNotFound` as harmless. For consistency, consider logging that case at `trace`/`debug` and keeping `warn` for real read errors.

3. **Files are read one at a time.** Each local-only file is read and parsed inside the `for` loop with `await`. `.github/agents` is usually small and the result is cached by TTL, so this is minor. If it matters, collect the candidates and use `Promise.all` (each with its own `try/catch`) so the reads run in parallel.

4. **`agent.header?.userInvocable` only reads the `user-invocable` key.** If older keys that also hide an agent from users are still supported in local agent files, they'll still show as warning entries here. Check that this matches how the Local picker in `agents/vscode-node/agentTypes.ts` decides visibility, so the two pickers agree.

5. **Local frontmatter changes may appear late (existing behaviour).** Options are cached by TTL, so editing `user-invocable` in a local file won't change the picker until the cache expires. This PR doesn't cause that, but it is now more visible because frontmatter affects the result.

### Code quality

- The new filtering is easier to read than the old one, which repeated `customAgents.status === 'fulfilled' ? … : []` in two places.
- `new PromptFileParser()` and `new TextDecoder()` are created once per file. Both are cheap, but they could be created once before the loop.
- The updated JSDoc for `localOnly` is accurate.

### Tests

The coverage is strong. The seven cases cover defaults, an explicit `true`, an explicit `false`, the all-hidden case (no group), remote settings winning over local ones, parsing edge cases with and without a working remote, and per-file errors. Smaller points:

- `expect(options.optionGroups).toEqual([])` in `omits the custom agent group when every remote agent is hidden` will break if another option group is ever added. Asserting that no `customAgents` group exists would be more robust.
- The `vi.mock('vscode')` additions (`FileSystemError` with a fixed `code = 'FileNotFound'`, `window.onDidChangeWindowState`, `asRelativePath`) are shared by every test in the file. Because `code` is fixed, every `FileSystemError` in tests is treated as not-found. That's fine for now, but a comment would help whoever adds the next filesystem error test.
- Changing `TestGitService.activeRepository` to a real `observableValue` and passing the real `MockFileSystemService` and `getTreatmentVariable` are reasonable test-setup improvements.
- There's no test for point 1 (a saved selection of a now-hidden agent). Add one if that path is handled.

### Security and performance

- No security concerns. Local files are only parsed for metadata, and errors are logged with the file URI and no content.
- Performance impact is small: extra reads only happen for local-only files, and results are cached.

**Verdict:** I'd approve this. Point 1, a saved selection still sending a hidden agent, is the one thing I'd check before calling the HTTP 400 fully fixed. The rest are minor improvements.

## Summary
The PR does three things:
1. **Remote agents:** it removes agents marked `user_invocable: false` from the Cloud "Custom Agents" picker.
2. **Local files:** it still matches local files against the full list of remote names, including hidden ones. Without this, a hidden remote agent would come back as a "Missing from …" warning entry.

## Code quality / correctness
- **Separating the matching list from the display list is correct.** `getLocalCustomAgentFiles(remoteAgents)` gets every remote agent, and only `userInvocableAgents` is shown (`copilotCloudSessionsProvider.ts:1255-1258`). This is the subtle part, and the test "keeps remote visibility authoritative when matching local files" checks it directly.
- **The `!== false` check is the right default.** An agent with no flag stays visible, and `disable_model_invocation` is left alone. This matches the meaning of `userInvocable` elsewhere (e.g. `automaticInstructionsCollector.spec.ts`).
- **Reusing `PromptFileParser`** through `platform/promptFiles/common/promptsService` (which re-exports it) is much better than a hand-written regex. The tests cover CRLF line endings, inline YAML comments, nested keys and body text that only mentions the flag. Those are exactly the cases a regex would get wrong.
- **Behavior change for unreadable files.** Before this PR, local-only files were never read, so every one showed up as a warning entry. Now a file that can't be read is logged and dropped from the picker. That's a reasonable choice, but showing it anyway would arguably be more conservative: it keeps the old behavior, and the entry is `locked` so it can't be selected. Either choice is fine; it would help to say which one is intended in a comment or the PR description.
- **Stale selections:** if a session already has a now-hidden agent selected (from before this change, or from the options cache), does anything check that selection against the new item list? If not, a user could still send the hidden agent and get the HTTP 400 that motivated this PR. I'd confirm how saved `chatSessionOption` values are handled when their item disappears.

- Local-only files are now read one after another (`await` inside the `for` loop). `.github/agents` is usually small, so this is minor. A `Promise.all` over the local-only candidates would remove the serial I/O from picker load, though. The result is also cached by `_optionsCache`, which limits the impact.
- `new TextDecoder()` and `new PromptFileParser()` are created once per file. Creating them once before the loop would be slightly cleaner. This is a nit.

## Security
- No concerns. The PR only reads files in the workspace's own `.github/agents` directory, using the existing file system service. The log message includes the file URI and the error text, which is in line with nearby logging.

## Tests
The coverage is strong. It includes default visibility, `display_name` fallback, the whole group disappearing when every agent is hidden, case-insensitive matching (`HiDdEn.AGENT.MD`), the remote fetch failing, and both deleted and unreadable files.

Small points:
- The global `vi.mock('vscode')` now defines `FileSystemError` with `code` fixed to `'FileNotFound'`. Any other test in this file that throws `FileSystemError` will always take the "not found" path in the outer `catch`. That's fine today, but a comment, or taking `code` as a constructor argument, would prevent surprises later.
- `TestGitService.activeRepository` is now a real `observableValue` shared across a `describe` block, and the new `beforeEach` sets it. - Possibly missing: a test where the remote fetch succeeds but `repoIds.length !== 1`. In that case local-only warnings should be suppressed and hidden remote agents still filtered out. This is optional.

## Nits
- The doc comment on `getLocalCustomAgentFiles` was updated to say "user-invocable local files", which is good. It could also mention that unreadable files are skipped.
