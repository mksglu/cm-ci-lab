**Review of PR 23009: Use local fixtures for outdated listings and cyclic build dependencies**

The PR is already merged. Overall it's a sound change. It removes TestPyPI network flakiness from four tests, and the diff looks correct. I only read the diff and did not run the tests.

**What's good**
- The `cyclic_build_dependency` test still checks the same behavior. The sdist's build requirement `circular-two` depends on `circular-one`, so `--no-binary` produces the cycle. The default run installs the wheel. It also drops the `--exclude-newer` and `unsafe-best-match` workarounds, which are no longer needed.
- It fixes a typo in the doc comment ("was a runtime dependency" is now "as a runtime dependency").
- It reuses existing helpers (`WheelBuilder`, `write_tar_gz`, `FindLinksServer`, `PackseServer`) and uses `?` rather than `unwrap`, which fits AGENTS.md.
- Renaming the fixtures to `default.toml` and `extra.toml` is reasonable now that they're shared. The updated references in `pip_compile.rs` are consistent.
- Each test has explicit `uv_snapshot!` invocations, with no loops and no `allow_duplicates`.

**Points to check**
1. **Feature gate.** The list tests moved from `test-pypi` to `test-python`. The `PackseServer` import is gated the same way, so it's consistent. The `pip_compile` tests that use `PackseServer` don't visibly carry a gate in this diff, so confirm which gate they use for the shared fixtures. The PR description says the tests pass with only `test-python` enabled, which suggests this was checked.
2. **Imports in `pip_install.rs`.** The diff doesn't show the imports for `WheelBuilder`, `write_tar_gz`, `FindLinksServer`, `fs` and `File`. CI presumably compiles, but check they are top-level imports and not gated differently from the test.
3. **Fixture name change.** `name = "pip-compile-default"` became `"default-index"`. If any snapshot or filter depends on the scenario name, such as a package-name prefix or a generated URL path, it could change. The passing resolver tests suggest this isn't an issue.
4. **Fixture side effects.** Adding `anyio 3.0.0`, `idna` and `sniffio` to the shared default index could alter resolution in the existing `pip compile` tests. For example, `anyio` now has a version between 1.0.0 and 4.3.0. The PR says the six resolver tests pass, so this looks fine. Adding a short comment in the TOML about why those packages exist would help future editors.
5. **Test naming.** `list_outdated_index` builds `index` and `extra_index` and passes the extra one through `--index-url`. The naming works, but a one-line comment would show that the CLI override intentionally replaces the env default.

**Performance and security**
- There are no concerns. The tests now only use loopback servers, which is faster and more deterministic. The PR says socket tracing confirmed only loopback connections.

**Verdict:** Looks good. The only follow-up I'd suggest is the small comment clarifications in items 4 and 5.

## Review of PR #23009: local fixtures for outdated listings and cyclic build dependencies

**Overall:** This is a good change. It removes three tests' reliance on test.pypi.org and pypi.org, and one of those caused a real CI flake from a 503. The tests keep their snapshots, so behavior coverage is unchanged. I found no blocking issues.

### Code quality and conventions
- **Fixture rename:** Renaming `pip-compile-default.toml` and `pip-compile-extra.toml` to `default.toml` and `extra.toml` fits their new use across test modules. All callers in `pip_compile.rs` are updated.
  - The fixtures' internal `name` values changed too (`default-index`, `extra-index`). Check that nothing else keys off the old names, such as generated scenario docs or the packse tooling.
- **Fixture setup:** The tests build their fixtures explicitly instead of through a hiding helper, as AGENTS.md prefers. The `cyclic_build_dependency` setup is verbose but readable. It reuses existing `WheelBuilder`, `write_tar_gz` and `FindLinksServer`.
- **Typo fix:** The doc comment is corrected ("`circular-one` was a runtime dependency" became "as a runtime dependency").
- **Env var inconsistency:** `list_outdated_columns` and `list_outdated_json` set `UV_DEFAULT_INDEX`, but `list_outdated_index` sets `UV_INDEX_URL`. The latter is the deprecated spelling and probably adds nothing here.
  - If `UV_INDEX_URL` was chosen so that `--index-url` replaces the default as it did before, a short comment would help.
  - Otherwise, using `UV_DEFAULT_INDEX` everywhere would be more consistent.
- **Imports:** The `#[cfg(feature = "test-python")]` import of `PackseServer` in `pip_list.rs` matches the gating of the tests that use it, so there is no unused-import warning when the feature is off. Using a top-level import also follows AGENTS.md.

### Potential bugs and risks
- **Feature gate:** The three list tests moved from `test-pypi` to `test-python`. That is correct, because they no longer touch the network but still need the 3.12 interpreter. Confirm that `PackseServer` itself needs no additional feature, such as a network or packse feature. The PR description says it passes with only `test-python`, so this looks fine.
- **Cyclic test fixture:** The sdist declares `build-backend = "circular_two"` but no such module exists. That is fine for the `--no-binary` case, which fails on cycle detection before any backend import. The snapshot would change if uv ever reordered those steps, so the doc comment could say the cycle is detected before the backend is loaded.
- **Dropped `exclude_newer`:** The old test pinned `with_exclude_newer("2025-01-02...")` to fix the TestPyPI state. That pin is no longer needed with local fixtures, so removing it is correct.
- **Shared fixtures:** Adding `anyio 3.0.0`, `idna` and `sniffio` to `default.toml` could change the resolver output of the other tests that share it. The PR says six resolver tests were re-run and passed. Anything that uses `indexes/default.toml` with an unpinned `anyio` should be checked in CI. The new 3.0.0 sits below 4.3.0, so highest-version resolution is unaffected.

### Performance
There is no production code change. Local servers should make these tests faster and more stable than network access did.

### Security
There are no concerns. The servers bind to loopback only, and the PR reports that socket tracing showed only loopback connections.

### Test coverage
- **Coverage:** The snapshots are unchanged, so coverage is preserved. The cyclic test still covers both the failing `--no-binary` build and the successful wheel install.
- **Remaining network dependency:** `list_outdated_git` still has a network dependency, outside this PR's scope. The test names involved are `list_outdated_columns`, `list_outdated_json` and `list_outdated_index`.
