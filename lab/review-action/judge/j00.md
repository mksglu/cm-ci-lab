**Review: PR #23009 — Use local fixtures for outdated listings and cyclic build dependencies**

This is a good, low-risk test change. It removes dependencies on TestPyPI and PyPI from four tests, and both rewrites still check what the old tests checked. I found nothing blocking, only a few small suggestions.

### Correctness

- **`cyclic_build_dependency`** still checks the important behaviour. `circular-two` lists `circular-one` as a runtime requirement, and the sdist for `circular-one` lists `circular-two` in `build-system.requires`. The cycle is found while installing build requirements, before uv tries to import `build-backend = "circular_two"`. So it's fine that the backend module doesn't exist. Using `--no-index --find-links` means the test can't reach the network. The test also fixes the comment typo ("was a runtime dependency" → "as").
- **Dropping `with_exclude_newer("2025-01-02…")`** is right. It only existed to freeze the TestPyPI contents.
- **Adding `anyio` 3.0.0 (+ `idna`, `sniffio`) to `default.toml`** doesn't change the existing `pip_compile` tests that share it:
  - `compile_index_url_unsafe_lowest` still picks 1.0.0, the lowest version.
  - `compile_index_url_unsafe_highest` still picks 4.3.0.
  - `compile_index_url_fallback_prefer_primary` still picks 3.5.0 from the extra index.
  - All of these use `--no-deps`, so the new transitive packages don't show up in their output.
- **Feature gates:**
  - Switching the `pip_list` tests from `test-pypi` to `test-python` is right. They need a 3.12 interpreter but no longer need the network.
  - `cyclic_build_dependency` still won't run without `test-pypi`, because the whole `pip_install` module is gated on `all(feature = "test-python", feature = "test-pypi")` (`crates/uv/tests/pip_install/main.rs:9`). That's fine; it just means the offline gain there is about reliability, not wider coverage.

### Suggestions

1. **Explain why the env var differs in `list_outdated_index`** (`crates/uv/tests/pip/pip_list.rs:408`). Two tests set `UV_DEFAULT_INDEX` and this one sets `UV_INDEX_URL`, which looks inconsistent. It's deliberate: `--default-index` is placed ahead of `--index-url` (`IndexOptions { index: default_index.combine(index), index_url, … }` in `crates/uv-cli/src/options.rs:559`). With `UV_DEFAULT_INDEX` set, the `--index-url <extra>` argument would no longer be the main index, and the test wouldn't show the override. A one-line comment would stop someone from "fixing" it later, e.g.:
   ```rust
   // Use `UV_INDEX_URL` so that the `--index-url` argument below replaces it; `UV_DEFAULT_INDEX`
   // would take precedence over `--index-url`.
   ```
   You could also just use `UV_INDEX_URL` in all three tests for consistency.

2. **Fixture names don't match their file names.** `default.toml` declares `name = "default-index"` and `extra.toml` declares `name = "extra-index"`. Packse doesn't need them to match, but `name = "default"` / `name = "extra"` would be easier to find with grep. The generic names also make these "the shared two-index fixture" for any test. It may be worth a top-of-file comment listing the version layout that tests depend on (default: `anyio` 1.0.0 / 3.0.0 / 4.3.0; extra: 3.5.0), so future edits don't quietly break `pip_list` and `pip_compile` snapshots.

3. **Small style point in `cyclic_build_dependency`.** It mixes `packages.join(...)` + `fs::write` with the `assert_fs` `ChildPath` API used elsewhere (`packages.child(filename).write_binary(&wheel)?`). Both styles exist in the file, so this is optional.

4. **Fixture coupling:** three `pip_list` tests now depend on the `pip_compile` fixtures. That's a fair trade for not duplicating them, and the rename makes the sharing explicit.

### Test coverage

- Snapshots stay the same as before (outdated `anyio 3.0.0 → 4.3.0`, and `→ 3.5.0` with the index override). No assertions were weakened.
- No new behaviour is covered, as you'd expect for a fixture migration.

### Performance and security

- Tests now hit loopback servers instead of the network, so they should be faster and less flaky. CI no longer depends on TestPyPI for these tests.
- No security concerns.

**Verdict:** Looks good to merge. The only change I'd ask for is the comment on why `list_outdated_index` uses `UV_INDEX_URL`.

# Review: PR #23009, "Use local fixtures for outdated listings and cyclic build dependencies"

## Summary
The PR moves four tests from TestPyPI/PyPI to local fixtures:
- **`pip_list.rs`:** `list_outdated_columns`, `list_outdated_json` and `list_outdated_index` now use the `PackseServer` indexes (renamed `default.toml` / `extra.toml`).
- **`pip_install.rs`:** `cyclic_build_dependency` now builds its wheels and sdist itself and serves them through `FindLinksServer`.

The snapshots stay the same apart from the new local URLs, which is a good sign that the behaviour under test hasn't changed. It also fixes a typo in a doc comment ("was a runtime dependency" → "as a runtime dependency").

## Correctness

- **Shared fixture change is safe for existing tests.** `default.toml` gains `anyio==3.0.0` (which depends on `idna` and `sniffio`), plus `idna 3.6` and `sniffio 1.3.1`. I checked the `pip_compile` tests that use this index:
  - `compile_index_url_unsafe_lowest` still picks `1.0.0`.
  - `compile_index_url_unsafe_highest` still picks `4.3.0`.
  - `compile_index_url_fallback_prefer_primary` still prefers the extra index's `3.5.0`.
  - The added version sits strictly between the existing ones, so the snapshots stay valid.
- **No stale references.** Nothing in `crates/` still uses the old `pip-compile-default.toml` / `pip-compile-extra.toml` names.
- **`cyclic_build_dependency` sdist.** `build-backend = "circular_two"` names a module that doesn't exist in the generated `circular-two` wheel. This works only because cycle detection happens while installing `build-system.requires`, before the backend is imported. If that order ever changes, the test would fail with a confusing import error instead of the cycle error. A one-line comment saying the backend is never reached would help future readers.

## Test design and coverage

1. **`list_outdated_index` covers less than before.** After `--index-url` replaces the index, the extra index only has `anyio`. `idna` and `sniffio` are installed but missing there, so the test now also depends on `pip list --outdated` silently skipping packages the index doesn't have. That's arguably fine behaviour, but it's a new implicit dependency. Two options:
   - add `idna` and `sniffio` to `extra.toml` so the test still checks only the override, or
   - note in a doc comment that missing packages are expected to be skipped.
2. **Inconsistent environment variables.** `list_outdated_columns` and `list_outdated_json` use `EnvVars::UV_DEFAULT_INDEX`, while `list_outdated_index` uses `EnvVars::UV_INDEX_URL`. I assume the legacy variable was picked so `--index-url` on the command line clearly overrides the same setting. If so, a short comment would explain the choice. Otherwise, use one variable throughout.
3. **`cyclic_build_dependency` is still gated on `test-pypi`.** The `pip_install` module is behind `#[cfg(all(feature = "test-python", feature = "test-pypi"))]` in `crates/uv/tests/pip_install/main.rs`. So even though the test no longer touches the network, it won't run in `test-python`-only configurations. That's fine for this PR, but if the goal is to shrink the `test-pypi` surface, a follow-up could move it to an ungated module. The PR description says the `test-python`-only check applied to "the three listing tests", which matches this.
4. **cfg gating in `pip_list.rs` is correct.** The `PackseServer` import is behind `#[cfg(feature = "test-python")]`, matching the only tests that use it, so builds without the feature won't warn about an unused import.
5. **Style follows AGENTS.md.** Setup is explicit (no helper hiding inputs), snapshots use `uv_snapshot!`, and each scenario is its own named test. The test still returns `Result<()>` and uses `?` instead of `.unwrap()`.

## Naming
- Renaming to `indexes/default.toml` / `extra.toml` makes sense now that more than `pip compile` uses them. The names are quite generic, though. If more multi-index fixtures are added, something like `multi-index-default.toml` would show which pair belongs together. This is a minor point.

## Performance and security
- **Performance:** a small gain. These tests no longer make network round-trips to TestPyPI/PyPI, and the CI flakiness from the 503 goes away.
- **Security:** no concerns. Everything is test-only, and the description says socket tracing recorded only loopback connections.

## Verdict
Good change that removes a real source of flakiness. The only follow-ups are small:
- a comment on the backend that never gets imported,
- making `list_outdated_index` explicit about skipping missing packages (or adding them to `extra.toml`),
- explaining or unifying the choice between `UV_INDEX_URL` and `UV_DEFAULT_INDEX`.
