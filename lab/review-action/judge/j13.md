# REVIEW A

# Review of PR #23017: Preserve inline comments when updating an existing dependency group

I read the diff only. I didn't build the PR or run its tests.

## Summary
The change only calls `fmt()` on the inline `dependency-groups` table when a new key is inserted. Adding a dependency to an existing group no longer reformats the table, so comments between keys survive. The approach is sound and the change is small.

## Issues

1. **The formatted output is worse.** The new snapshot shows the edited array rendered like this:
   ```toml
   dependency-groups = {
       dev = [
       "ok==1.0.0",
   ], # Local development
       # Release tests run separately.
       release = [],
   }
   ```
   The element and the closing `]` are not indented. This is probably because `add_dependency` expands the array and `fmt()` used to normalize that. The snapshot locks in an ugly layout.
   - It is a visible regression for anyone with an inline table who has no comments. Before this PR they got `dev = ["ok==1.0.0"]`.
   - Consider decorating the edited array (for example, resetting its prefix and suffix, or fixing the trailing/indent decor) so it matches the table's style.
   - Alternatively, run `fmt()` only when the table has no comments, or fix up just the touched value.
   - At minimum, call this tradeoff out in the PR description.

2. **Unrelated refactor in the second function.** The group-creation function (around line 681) was restructured with an early return, and its comments were removed. This is not needed for the fix.
   - It is reasonable cleanup, but it makes the diff larger.
   - It also drops the explanatory comments about sorting and about reformatting inline tables. The new comment in the first function is good, but the second function now has none.
   - The early return is behavior-preserving, but `was_sorted` is still computed before it, which is wasted work on the common path.

3. **Behavior is still inconsistent when a new group is added.** `fmt()` still strips comments in that case. That is arguably out of scope, but the removed comment ("you can't put comments between items in an inline table anyway") was wrong, as this PR shows. Mention the remaining limitation somewhere, or consider fixing it too.

## Tests
- Only one scenario is covered (`--dev` on an existing group). `uv add --group <name>` on an existing group goes through the same code path. Per the repo's AGENTS.md, don't duplicate it, but check whether an existing inline-table test already covers the no-comment case. Its snapshot may need updating if the array layout changed, and the diff shows no changes to such tests, which is worth confirming.
- There is no test that inserting a new group into an inline table still formats correctly. Existing tests probably cover it, but verify.
- The `uv_snapshot!(..., @"exit_code: 0 (success)")` form with `--frozen` matches the style used elsewhere. Check that nearby tests also snapshot the full output with the empty stdout/stderr sections, as the repo's convention requires.
- The test is placed just before `add_group_comment`, which is fine. A doc comment explaining the regression scenario would help, as AGENTS.md prefers.

## Other considerations
- There are no security or performance concerns.
- The code follows the repo conventions: no unwraps or panics, and it uses `if let`. Nested `if new_group { ... if let ... }` could use a let chain, but a let chain wouldn't read better there.

**Review of PR #23017: Preserve inline comments when updating an existing dependency group**

The change is small, targeted and correct. I have a few suggestions, none of them blocking. The PR is already merged, so these are follow-ups.

**Code quality**
- In `add_dependency_group` (the second hunk), the early `return Ok(())` when the group already exists is cleaner than the old `group_exists` flag. It also fixes the same comment-erasing reformat on the existing-group path, which the PR description doesn't mention.

- Both hunks now repeat the same "get inline table, then `fmt()`" block. A small helper could remove that duplication, but it is optional.
- The new comment ("Only inserting a key changes the table layout…") explains the rationale well and doesn't refer to past behavior.
- The old comment said "Reformatting can drop comments between keys, but you can't put comments between items in an inline table anyway." That claim was wrong, since TOML 1.1 allows comments in inline tables. Removing it is correct.

**Potential issues**
- Adding a group to an inline table still calls `fmt()`, so comments on the surrounding keys are still dropped in that case. That is a reasonable scope for this PR. - The first hunk still calls `fmt()` on a freshly inserted group, so `was_sorted` and `sort_values` behave the same as before. I see no regression there.

- There are no security concerns.
