# REVIEW A

**Review of PR 23009: use local fixtures for outdated listings and cyclic build dependencies**

The PR is already merged. Overall it's a sound change that removes network flakiness from four tests.

**What looks good**
- `cyclic_build_dependency` no longer depends on TestPyPI. It builds two wheels and an sdist locally. The build cycle is still exercised: `circular-one` builds with `circular-two`, which needs `circular-one`. The wheel install path is also still covered.
- The fixture renames (`pip-compile-default.toml` to `default.toml`, and likewise for `extra.toml`) and the call-site updates are consistent. The fixtures are now shared across the pip compile and pip list tests.
- The doc-comment typo is fixed ("was a runtime dependency" is now "as a runtime dependency").
- Using `.arg(extra_index.index_url())` in place of the hard-coded TestPyPI URL follows the existing `PackseServer` style.
- Explicit setup and snapshots are kept, with no loops or helper hiding, as AGENTS.md asks.

**Issues and suggestions**
1. **Feature gate change.** The three list tests moved from `test-pypi` to `test-python`. That is reasonable, since they now need only a Python interpreter and local servers. `PackseServer` is imported under `#[cfg(feature = "test-python")]`, which matches the gate. Check that `PackseServer` itself isn't gated on a different feature in `uv_test`. The PR says the tests pass with only `test-python`, which suggests it isn't.
2. **Fixture coupling.** `anyio` 3.0.0 is added to `default.toml`, along with `idna` and `sniffio`, so the shared default index now serves more packages. Adding a version to a fixture shared with the `compile_index_url_*` tests could change their resolutions. For example, an `anyio` range or lowest-resolution test could now pick 3.0.0. The PR says the six resolver tests passed, so this looks fine. Still, a comment in the fixture noting that the list tests depend on 3.0.0 would help future editors.
3. **`list_outdated_index` snapshot.** The `UV_INDEX_URL` env var is set on the context, and the `--index-url` flag then overrides it with the extra index. This is a valid way to test the override. A short comment saying the env var is deliberately overridden would make the intent clearer.
4. **`cyclic_build_dependency` setup.** The fixture is about 20 lines of inline setup. That fits the "explicit fixtures" guidance. The sdist's `build-backend = "circular_two"` relies on the backend module name resolving to the built wheel. This is what produces the cycle error, and the snapshot confirms it. A one-line comment on that would help readers.
5. **Minor.** The test now returns `Result<()>`, which is fine. `"0.2.0".parse()?` is repeated as a string in the pyproject. Deriving both from one constant would avoid drift, but this is a nit.

**Performance and security**
There are no concerns. The servers bind to loopback only, and the PR reports that socket tracing showed only loopback connections. Tests are faster and no longer depend on external services.

**Test coverage**
Coverage is unchanged and now deterministic. No new behavior was added, so no new tests are needed.

I'd approve it. The points above are all minor.
