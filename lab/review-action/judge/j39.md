# REVIEW A

**Review of PR 37046: distrust compromised eMudhra CAs.** The PR is already merged, so this is a post-merge review.

**Summary:** The change bumps `rustls-webpki` to 0.103.16, `webpki-roots` and `webpki-root-certs` to 1.0.10, `aws-lc-rs` to 1.18.2 and `deno_graph` to 0.111.1. It also moves the ML-DSA code from `aws_lc_rs::unstable::signature` to the stable `aws_lc_rs::signature` API. The security intent is sound and the diff is small and focused.

**Concerns**

1. **Two `aws-lc-sys` versions in the lockfile.** `aws-lc-rs` now pulls in `aws-lc-sys 0.46.0`. The workspace still pins `aws-lc-sys = 0.40.0` for `deno_crypto_provider` and `deno_node`, so both versions are built and linked.
   - This increases build time and binary size.
   - Two copies of AWS-LC's C symbols can collide at link time. `aws-lc-sys` normally prefixes its symbols per version, so this is probably fine, but CI should confirm it.
   - `deno_crypto_provider` and `deno_node` call `aws-lc-sys` FFI directly. Their key and EVP objects can't be passed to `aws-lc-rs` APIs, because they come from a different copy of the library.
   - Bump the workspace `aws-lc-sys` to 0.46 in a follow-up to deduplicate.

2. **Behavior change in `to_pkcs8v1()`.** The PR says it preserves the existing PKCS#8 export format. A spec or unit test that checks exported ML-DSA PKCS#8 bytes, or round-trips through `importKey`, should cover that. I didn't see test changes in the diff. The existing WebCrypto ML-DSA tests probably cover it, but one explicit assertion would guard against a silent format change.

3. **No regression test for the distrust itself.** This is hard to unit-test because it needs a chain through a compromised key. A cheap check would be asserting that `emSign ECC Root CA - G3` is absent from the bundled roots, so a later dependency downgrade or a re-added root fails loudly.

4. **Loose version requirement.** `rustls-webpki = "0.103.16"` is a caret requirement and allows later 0.103.x releases. That's fine, since the lockfile pins the exact version and the floor is what matters for the security fix. `webpki-roots 0.26.11` is only a compatibility wrapper that re-exports 1.0.10. Both `webpki-roots 0.26.11` and `1.0.10` now appear in the lockfile, which is harmless but worth knowing.

5. **Major-version bumps of `webpki-roots` and `webpki-root-certs`** (0.26 → 1.0). The PR validates only `deno_tls`, `deno_node` and `deno_graph` locally, and relies on CI for the full workspace. The diff shows no other source changes, so API breakage looks unlikely. Check that the `webpki_root_certs::TLS_SERVER_ROOT_CERTS` and `webpki_roots::TLS_SERVER_ROOTS` consumers still compile and behave the same.

6. **Process.** The PR bundles a security fix, an ML-DSA API migration and a `deno_graph` bump. CLAUDE.md asks for minimal changes without drive-by edits. The ML-DSA migration is justified as a CI-deprecation fix tied to the `aws-lc-rs` bump, but the description should say so more clearly. The PR body also has two unrelated sections: the `deno_graph` note is pasted at the end.

**Positives**
- The PR description clearly links the upstream fixes and lists validation steps.
- The ML-DSA change is mechanical and keeps behavior the same.
- It moves off an `unstable` API, which reduces future breakage.

**Verdict:** Approve. The follow-ups are to dedupe `aws-lc-sys`, add an ML-DSA PKCS#8 export assertion, and add a check that the removed root stays out of the bundle.

# Review of PR 37046: distrust compromised eMudhra CAs

The PR is already merged. The change looks correct and well-scoped. I haven't built it, so this review is from the diff alone.

## What it does
- It raises `rustls-webpki` to 0.103.16, which rejects the compromised eMudhra keys, including cross-signed paths.
- It moves `webpki-roots` and `webpki-root-certs` to 1.0.10, which drops `emSign ECC Root CA - G3`. The transitive 0.26.x users (reqwest and hyper-rustls) now resolve to the 0.26.11 shim, which forwards to 1.0.10. That means every TLS path sees the same fixed bundle.
- It raises `aws-lc-rs` to 1.18.2 and moves the ML-DSA imports from `unstable::signature` to the stable `signature` module. It uses `to_pkcs8v1()` to keep the exported PKCS#8 format unchanged.
- It bumps `deno_graph` to 0.111.1.

## Points worth checking

1. **Two `aws-lc-sys` versions in the lockfile.**
   - `aws-lc-rs` 1.18.2 pulls in `aws-lc-sys` 0.46.0. `deno_crypto` and `deno_crypto_provider` still use the workspace pin of 0.40.0.
   - The result is two copies of AWS-LC compiled and linked. That adds build time and binary size, and it risks duplicate C symbols.
   - aws-lc-sys normally prefixes its symbols per version, which should avoid link clashes.
   - It is also worth confirming that `deno_crypto` and `deno_crypto_provider` don't mix types or pointers between the two copies. As far as I can tell, they use `-sys` directly and `-rs` separately.
   - Consider bumping the workspace `aws-lc-sys` pin to 0.46 in a follow-up so there is only one copy. Check whether the `prebuilt-nasm` feature is still available at that version.

2. **`to_pkcs8v1()` behaviour.** The PR says the output format is preserved. A spec or unit test should confirm that ML-DSA PKCS#8 export still matches the previous bytes and still round-trips through import. I don't see a test change in this diff. Existing WPT/unit coverage may already do this, but it should be confirmed.

3. **Test coverage for the distrust itself.** There is no test showing that a chain through a compromised eMudhra key is rejected. That is understandable, because it needs fixtures from the affected CA. Even so, a small unit test could check that `webpki_roots::TLS_SERVER_ROOTS` and `webpki_root_certs` don't contain the removed subject. That would guard against regressions if someone pins older versions.

4. **Version constraints.**
   - `rustls-webpki = "0.103.16"` is a floor, not an exact pin. That is fine, since the lockfile pins the resolved version.
   - `webpki-roots = "1.0.10"` also works as a floor. Both give downstream consumers the security fix as a minimum.

5. **PR hygiene.** The PR mixes the TLS fix, an AWS-LC bump with an API migration, and the `deno_graph` bump. The AWS-LC change is justified as required by the verifier. The deno_graph bump was appended later and could have been a separate PR, per the repo's "minimal changes" guidance.

## Security
Nothing concerning. The change tightens trust, using upstream-published fixes. Updating `webpki-root-certs` 0.26 to 1.x also covers the native/extra roots path, which is easy to miss.

## Verdict
Looks good. The suggested follow-ups are to unify `aws-lc-sys` and to add a regression test for the removed root and for the PKCS#8 export.
