## Review: PR #345283 — ci: run the selected unit tests (`--runList`) in parallel workers

A new `getWorkerCountForFiles` sizes the worker pool from how many listed files will actually run. The "Running the N test files of the M listed" message is now printed once, by the parent process. ### Correctness: what I checked
- **Electron single-worker path** (`test/unit/electron/index.js`, `firstRunArgs = { ...args, run: files }`):
  - Because `workersApply` requires `workerCount > 1`, `getWorkerCountForFiles` only returns 1 when there are 0 or 1 files. So the `argv` JSON passed in the window URL stays tiny.
  - Reruns rebuild `runArgs` from `args` (line ~816), not from `firstRunArgs`, so the injected `run` doesn't leak into later attempts.
  - The renderer's `opts.run` branch strips `.js`, which is right for the `vs/...test.js` paths that `findTestFiles` returns.
